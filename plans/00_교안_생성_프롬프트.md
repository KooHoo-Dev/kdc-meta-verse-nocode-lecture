## A. 붙여넣어 쓰는 실행 프롬프트

```
NN차시 「<시트 제목>」 노코드 교안 + VOD 스크립트를 만들어줘.

원본: <Docs/0. Origin/... 경로 또는 "원본 없음 — 신규 설계">
시트 설명: <시트의 교육 내용 칸 원문 그대로>
선행 차시: <NN-1>차시에서 확정된 용어·산출물을 이어받을 것
필요 교육용 컴포넌트: <plans/02_유니티_프로젝트_작업계획.md 의 해당 차시 행>

작업 순서:
1. references/ 골든 레퍼런스 2개를 먼저 읽어라
2. 직전 차시 산출물 2개를 읽고 용어·실습 번호·예고 내용을 확인해라
3. 실습 ①~④를 먼저 확정해라 (아래 B의 난이도 계단을 따를 것)
4. 노코드 교안 → VOD 스크립트 순으로 작성해라
5. 아래 E의 자가 검증을 전부 돌리고 결과를 보고해라

교육용 컴포넌트가 원본/계획에 없으면 임의로 만들지 말고 명세를 제안한 뒤 확인받아라.
```

## B. 실습 설계 — 난이도 계단

실습은 **넷을 한 덩어리로 설계**합니다. 개별로 만들면 난이도가 튑니다.

| 실습 | 역할 | 수강생이 하는 일 | 실패해도 되는가 |
| :--- | :--- | :--- | :--- |
| **①** | **확인·체험** | 눈으로 보고 클릭만. 만드는 게 없음 | 실패할 게 없음 |
| **②** | **값 조작** | 숫자·체크박스·색을 바꿔봄 | 되돌리면 됨 |
| **③** | **그 차시의 결과물** ★ | 실제로 뭔가를 완성함 | **여기만 시간을 넉넉히** |
| **④** | **심화 · 선택** | 떼보기, 여러 개 한 번에, 응용 | 안 해도 됨 |

- **실습 ③이 그 차시의 제목**입니다. 1차시=회전하는 큐브, 3차시=자동차. ③이 안 잡히면 그 차시는 설계가 안 된 것입니다.
- ④에는 반드시 **(선택)** 을 붙입니다. 시간이 모자란 수강생의 탈출구입니다.
- 실습마다 4종 세트 고정: `> 🎯 **목표**` → 번호 순서(결과를 `→` 로 병기) → `<details>` 접기 `✅ 확인해보세요` → `> ⚠️ **잘 안 되신다면**`
- **트러블슈팅은 원인을 하나로 좁혀서** 씁니다. "여러 원인이 있을 수 있습니다"는 금지 — 초보자는 선택지를 못 고릅니다.

## C. 교육용 컴포넌트 명세 — 표 3종

실습이 성립하려면 완성 스크립트가 필요합니다. **교안에는 코드가 아니라 아래 표만** 실립니다.

```markdown
### **N.1 조절할 수 있는 값**
| Inspector 항목 | 무슨 뜻인가요 | 어떻게 바꾸나요 |

### **N.2 버튼에 연결할 수 있는 동작**
| 동작 이름 | 무슨 일을 하나요 |

### **N.3 특별한 칸 하나**   ← 이벤트 칸이 있을 때만
| 항목 | 무슨 뜻인가요 |
```

원본에 해당 스크립트가 없으면 **명세를 제안하고 확인받은 뒤** 진행합니다. 임의 생성 금지.

> 모양 부품은 *옷의 본*, 보이는 부품은 *입혀서 보여주기*. **둘 다 있어야 화면에 나온다**를 14차시 실습 ①에서 몸으로 확인시킵니다.

> 새 용어를 확정하면 **이 표에 먼저 추가한 뒤** 본문을 쓸 것.

### D-2. 앞뒤 연결 4종

1. **이전 차시 콜백** — "1차시에 하셨던 그것", "2차시에 만든 재료를 씁니다"
2. **오늘의 목표 앞 `> 💬`** — "N-1차시와 오늘의 차이"를 한 문장으로
3. **다음 차시 예고** — 다음 차시가 해결해줄 **오늘의 미해결 질문**을 명시 ("0.55는 어느 쪽인가요? → 다음 시간에")
4. **준비물 체크박스** — 이전 차시 산출물 저장 + 다음 차시에 필요한 파일 확인

### D-3. 미루기 문구 통일

문법·라이프사이클·좌표 이론 질문은 **답하지 말고** 미룹니다.
VOD 스크립트의 예상 질문 표에는 `**답하지 마세요.** "N차시에서 다룹니다"로 통일` 로 적습니다.

## E. 자가 검증 (산출 후 반드시 실행)

```bash
grep -nE "변수|필드|메서드|함수|매개변수|상속|컴파일|프레임|클래스|인스턴스|렌더링|public|private" NN_*_nocode.md NN_*_vod_script.md
```
→ **치환표 안에만** 걸려야 통과. 본문에 걸리면 수정.

```bash
grep -n '```csharp' NN_*.md
```
→ 0건이어야 통과. 대응 관계는 ` ``` ` 일반 블록의 `──→` 도식으로만.

```bash
grep -nE '^\s*(!!!|\?\?\?)|:material-|:octicons-|=== "' NN_*.md
```
→ 0건이어야 통과. 사이트 전용 문법 잔재. 강조 블록은 `> 이모지 **제목**`, 접기는 `<details>` — `CLAUDE.md` 「마크다운 표기 규칙」 참조.

수동 대조 4가지:
- [ ] 교안 실습 번호 ①~④ ↔ 스크립트 `⏸ 실습` 번호 일치
- [ ] 정리 문제 개수 == `<summary>✅ 정답 보기` 개수
- [ ] 타임라인 구간이 `00:00` → `00:50` 까지 **빈틈·중복 없이** 연속
- [ ] Play 중 값 소실 경고가 교안 `> 🚨` + 스크립트 육성 대사 **양쪽**에

## F. VOD 스크립트 — 1~3차시에서 확정된 추가 규칙

레퍼런스에 명시되지 않았으나 실제 작성에서 굳어진 것들입니다.

### F-1. 실패 장면을 자르지 않는다

강사가 실수하는 장면을 **의도적으로 담고, 복구까지 보여줍니다.**

| 담을 실패 | 복구 |
| :--- | :--- |
| Scene에서 시점을 잃어버림 | 물건 클릭 후 `F` |
| 화살표 대신 몸통을 끌어서 물건이 날아감 | `Ctrl + Z` |
| 드래그를 빈 공간에 놓아 아무 일도 안 일어남 | 다시 정확히 놓기 |

→ 스크립트에 `- **실패하는 장면을 한 번 보여주고 성공시켜주세요.**` 형태의 일반 bullet로 표기.

### F-2. 결과물을 오프닝에서 먼저 보여준다

만드는 게 있는 차시(실습 ③이 무거운 차시)는 **00:00 화면에 완성본을 띄우고 시작**합니다.
"오늘 이걸 만드십니다"가 50분을 버티게 합니다.

### F-3. 정지 안내 대사 3요소

1. **"영상을 잠깐 멈춰주세요"**
2. 무엇을 확인하면 성공인지 (**결과 기준**, 순서가 아니라)
3. **"다 하셨으면 재생을 눌러주세요"**

### F-4. 주의(⚠️) 블록은 최소로

넣는 기준은 **"안 넣으면 수강생이 실제로 막히는가"** 하나뿐입니다.
1~3차시 기준 차시당 2~3개를 넘기지 않았습니다.

### F-5. 넣지 않는 것 (레퍼런스에서 의도적으로 제거)

`CLAUDE.md` 의 목록을 그대로 따릅니다. 특히 **강사 경험담·표기 범례·녹화 체크리스트·분량 조절 표**는 생성하지 않습니다.

## G. 심리적 안전 문구 배치 지점

| 위치 | 문구 성격 | 예 |
| :--- | :--- | :--- |
| 첫 `> ℹ️` | **코드 안 씀** 선언 | "코드를 한 줄도 쓰지 않습니다" |
| 복잡한 표·화면 직후 | 면제 | "지금은 몰라도 됩니다" |
| 실습 도입 | 실패 허용 | "안 되셔도 괜찮습니다" |
| 실습 ② 부근 | 파괴 허용 | "마음껏 망가뜨리셔도 됩니다" |
| 오류·경고 등장 | 재해석 | "혼내는 게 아니라 알려주는 것입니다" |
| 마무리 | 성취 | "충분히 잘하셨어요" |

> **"어렵지 않아요"는 쓰지 않습니다.** 불안은 난이도가 아니라 '뭘 해야 할지 모름'에서 옵니다.
> **"안 하셔도 됩니다" / "되돌릴 수 있습니다"** 가 효과적입니다.
