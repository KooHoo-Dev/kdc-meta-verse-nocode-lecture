# 에디터 도구 — 씬 빌더 · 실습 점검기 작업 계획

> 목표: **13 ~ 32차시의 완성 씬을 코드로 만들고**, 수강생이 **스스로 막힌 곳을 찾을 수 있는 점검기**를 함께 배포합니다.
> 작성: 2026-08-23

---

## 1. 왜 하는가

| | |
| :--- | :--- |
| **강사가 저자가 아닙니다** | 완성 결과 화면을 만들어 **검증해서 전달**해야 합니다 |
| **VOD 라 질문을 못 받습니다** | 수강생이 막혀도 물어볼 곳이 없습니다 |
| **U-6 이 손으로 하기엔 큽니다** | 체크 단계 **71개** · 이벤트 연결 **22개** · 저장할 씬 **6개** |
| **U-7 결과가 나오면 다시** | `❌` 하나에 **최대 6개 씬**을 고쳐야 합니다 |

---

## 2. 도구는 두 개입니다

| | **씬 빌더** | **실습 점검기** |
| :--- | :--- | :--- |
| 누가 | 저자 | **수강생** |
| 위치 | `Assets/_SceneBuilder/Editor/` | `Assets/_NoCodeKit/Editor/` |
| 배포 | ❌ 안 함 | ✅ **`.unitypackage` 에 포함** |
| 하는 일 | 씬을 **만든다** | 씬을 **검사한다** |
| 언제 | 교안 제작 때 | 실습 중 **막힐 때마다** |

> ⚠️ **빌더가 `_NoCodeKit` 안에 들어가면 안 됩니다**
>
> `_NoCodeKit` 은 수강생에게 통째로 나갑니다. 빌더가 딸려가면 정답 씬 생성기를 같이 주는 셈입니다.

**빌더는 점검기를 재사용합니다.** 씬을 만든 뒤 점검기를 돌려 통과하는지 확인합니다.
정답 씬이 도구를 통과 못 하면 **둘 중 하나가 틀린 것**이므로, 점검기 자체도 같이 검증됩니다.

## 4. 점검기 설계

### 4-1. 두 층으로 나눕니다

| 층 | 언제 | 무엇을 | 오탐 위험 |
| :--- | :--- | :--- | :---: |
| **상시 점검** | 메뉴 + **▶ 누를 때 자동** | 빈 칸 · 끊어진 연결 · Dynamic/Static · Tag | 거의 없음 |
| **차시 확인** | 메뉴 **수동 전용** | 그 차시의 목표가 갖춰졌는지 | 낮음 (아래) |

**차시 확인을 자동 실행에서 뺀 이유** — 실습 진행 중에는 미완성이 정상입니다.
자동으로 돌리면 매번 "아직 안 했다" 경고가 쏟아져서 **수강생이 도구를 무시하게 됩니다.**

### 4-2. 🔴 이름으로 찾지 않습니다

차시 목표 검사의 가장 큰 위험은 **수강생이 이름을 다르게 지었을 때 오탐**입니다.
교안은 `Gun` 이라 지으라고 하지만, `총` 이라 지어도 실습은 성립합니다.

**해결 — 이름 대신 부품으로 찾습니다.**

| 검사하고 싶은 것 | ❌ 이름으로 | ✅ 부품으로 |
| :--- | :--- | :--- |
| 총이 있는가 | `Find("Gun")` | `SimpleGun` 이 붙은 것이 씬에 있는가 |
| 마우스 조작이 붙었나 | `Find("Gun")` 의 부품 확인 | `SimpleGun` 과 **같은 그릇**에 `MouseShooter` 가 있는가 |
| 총이 카메라 자식인가 | 이름으로 부모 추적 | `SimpleGun` 의 **조상에 `Camera`** 가 있는가 |
| 표적이 틀인가 | 이름 | `TargetLauncher.targetPrefab` 이 **프리팹인가** |

**차시 목표는 거의 전부 이름 없이 표현됩니다.** 이름은 **메시지에만** 씁니다 — *"[Gun] 총알 틀이 비어 있습니다"*.

### 4-3. 상시 점검이 잡는 것

| 증상 | 수강생이 겪는 것 | 검출 방법 |
| :--- | :--- | :--- |
| 빈 칸 | "아무 일도 안 일어나요" | 필수 칸이 비었는지 (§7-4) |
| **끊어진 연결** | **"어제까진 됐는데요"** | `m_Target` 이 비었는지 |
| 동작 안 고름 | "칸은 만들었는데" | `m_MethodName` 이 비었는지 |
| **Dynamic/Static 오선택** | **"연결했는데 안 바뀌어요"** | `m_Mode != 0` (`UnityEvent<T>` 에 한해) |
| Tag 누락 | "맞아도 반응이 없어요" | 적어둔 이름표가 **등록됐는지** |

> 📝 **일부러 안 잡는 것 두 가지**
>
> | | 왜 |
> | :--- | :--- |
> | **연결이 0개인 이벤트 칸** | 비어 있는 게 정상인 칸이 많습니다 (`Projectile.On Miss` 등). 진행 중엔 대부분 비어 있고요 |
> | **씬에 그 이름표를 단 것이 있는지** | 총알·표적은 **실행 중에 만들어집니다.** 씬에 없는 게 정상이라 오탐이 납니다 |

> ✅ **Dynamic/Static 이 이 강의 최대 함정입니다**
>
> 18 · 25 · 26차시에서 반복됩니다. 위쪽 `Dynamic float` 대신 아래쪽 `Static Parameters` 를 고르면
> **연결은 됐는데 화면이 안 바뀝니다.** 수강생이 원인을 절대 못 찾는 종류예요.
>
> 연결마다 `PersistentListenerMode` 가 저장돼 있어서, `EventDefined`(=Dynamic) 인지 아닌지 **코드로 구분됩니다.**

> ✅ **확인 완료 (2026-08-23)**
>
> Unity DLL 메타데이터와 실제 씬 파일 양쪽에서 확정했습니다. **설계 변경 없습니다.** → §7-1

### 4-4. 끊어진 연결이 특히 중요합니다

오브젝트 이름을 바꾸거나 지웠다 다시 만들면 연결이 **조용히 끊어집니다.**
Inspector 에서는 빈 칸처럼 보여서 **수강생은 끊어진 줄도 모릅니다.**

### 4-5. 빈 칸 검사 — 부품이 이미 정해둔 것만

*"참조 칸을 전부 훑고 예외를 빼자"* 로 시작했는데, **오탐이 납니다.**
`RendererSwitcher` 는 칸이 셋인데 하나만 써도 정상이고, `MuzzleFlashPlayer` 는 둘 중 하나만 있으면 됩니다.

**대신 부품이 스스로 `Debug.LogWarning` 을 내는 칸만** 넣었습니다.
저자가 이미 "무엇이 필수인지" 판단해둔 결과이므로, **추측이 들어가지 않습니다.** → §7-4

**런타임 코드(`_NoCodeKit/Scripts/`)를 안 건드립니다.** 검사 규칙은 전부 Editor 쪽에만 둡니다.

### 4-6. 메시지 원칙

```
❌  NullReferenceException: bulletPrefab is null
✅  [Gun] 총알 틀이 비어 있어서 총알이 안 나갑니다.
    Prefabs 폴더의 Bullet 을 Bullet Prefab 칸에 끌어다 놓아주세요.
```

- `CLAUDE.md` 치환표를 그대로 적용 — **변수 · 필드 · 참조 · 널** 안 씀
- `Debug.LogWarning(메시지, 그오브젝트)` — **콘솔 줄을 클릭하면 Hierarchy 에서 선택**됩니다
- 앞에 `[오브젝트이름]` 을 붙여 어디인지 바로 보이게

## 5. 빌더 설계

### 5-1. 체인 방식 — 한 번 돌려 12개 씬

```
M1 조립 → 저장(22_완성) → M2 → 저장(23_완성) → … → 저장(27_완성)
```

**`NN_시작` = `(NN-1)_완성`** 이므로 체인 하나로 **완성 6개 + 시작 6개**가 나옵니다.
`plans/02` §4-2 가 요구하는 "차시별 시작 씬" 이 같이 해결됩니다.

### 5-2. ⚠️ 이름표 · 재질 · 틀을 **미리 만들면 안 됩니다**

처음엔 *"씬보다 먼저 Tag · 재질 · 프리팹을 만들어두자"* 로 잡았는데, **틀렸습니다.**

**그것들이 곧 차시 내용입니다.**

| 만드는 것 | 어느 차시가 만드나 | 교안 근거 |
| :--- | :---: | :--- |
| 색깔 재료 | **13** | 실습 ③ *"재료를 만들어서 입혀보기"* |
| 이름표(Tag) | **21** | *"`Add Tag...` 로 만들기 — 여기까지는 아직 아무한테도 안 달림"* |
| 접시 틀 | **23** | 실습 ① *"접시 틀 만들기"* |
| 총알 틀 | **24** | 실습 ② *"총알 틀 만들기"* |
| 효과 틀 | **25** | *"`Prefabs` 폴더로 끌어다 놓아 틀로 만들고"* |

미리 만들어두면 **`22_완성` 에 아직 없어야 할 것들이 들어갑니다.**

> ✅ **대신 0단계는 "빌더 기반" 입니다**
>
> 차시 빌더들이 공통으로 쓰는 **도구**만 만듭니다.
> 이름표 · 재질 · 틀은 **그것을 가르치는 차시의 빌더가** 도구를 불러 만듭니다.
>
> 순서 문제는 저절로 풀립니다 — 23차시 빌더가 접시 틀을 만들기 **직전에** `EnsureTag` 를 부르면 되니까요.

### 5-3. 스크린샷

**지금 교안 30개에 이미지가 0장입니다.** 강사가 저자가 아니라 특히 아픕니다.

씬을 만든 뒤 이어서 캡처합니다. `Docs/1. NoCode/<섹션>/images/NN_완성.png`

> ⚠️ **캡처 전에 XR 을 꺼야 합니다**
>
> 지금 `Initialize XR on Startup` 이 켜져 있어서 ▶ 를 누르면 OpenXR 초기화를 시도합니다 (`plans/05` §0-2).
> 빌더가 캡처 전에 자동으로 끄고, 끝나면 되돌리게 만듭니다.

## 6. ⚠️ 미리 알아야 할 함정

| | |
| :--- | :--- |
| **Edit 모드 생성** | `Undo.RegisterCreatedObjectUndo` + `EditorSceneManager.MarkSceneDirty` 없으면 **저장이 안 되거나 되돌리기가 깨집니다** |
| 🔴 **코드로 붙인 부품의 이벤트 칸** | `AddComponent` 로 붙이면 `UnityEvent` 칸이 **비어 있습니다.** 거기에 연결하려 하면 터집니다. **반드시 `BuildKit.Add<T>()`** 를 쓰세요 (§6-1) |
| **URP 재질** | `Shader.Find("Universal Render Pipeline/Lit")` |
| **XR 초기화** | 캡처·Play 전에 꺼야 합니다 |
| **오탐 한 번** | 수강생은 그 뒤로 도구를 안 믿습니다. **확실한 것만** |
| **경고 쇄도** | 차시 확인을 자동 실행에 넣지 않는 이유 |
| **`.meta`** | 새로 만든 스크립트 · 프리팹 · 재질은 **`.meta` 를 짝으로 커밋** (`HANDOFF.md` §3) |

### 6-1. 이벤트 칸이 비어 있는 문제 — 자체 시험에서 잡혔습니다

부품 22개의 이벤트 칸에 **초기값이 없습니다.**

```csharp
public UnityEvent onGameStart;      // ← 초기값 없음
```

| | |
| :--- | :--- |
| **Inspector 로 붙이면** | 유니티가 직렬화하면서 채워줍니다. **수강생은 안 겪습니다** |
| **코드로 붙이면** | 빈 채로 남습니다 → `UnityEventTools` 가 그대로 터집니다 |

**부품 소스는 고치지 않았습니다.** 배포되는 코드이고, 수강생 경로에는 문제가 없기 때문입니다.
대신 `BuildKit.Add<T>()` 가 붙인 직후 빈 이벤트 칸을 만들어둡니다.

> 💡 **부품들은 이미 `onFired?.Invoke()` 처럼 방어하고 있습니다**
>
> 그래서 실행 중에는 비어 있어도 안 터집니다. **연결을 거는 쪽만** 문제였습니다.

#### 7-1. 확인 결과 — 설계 변경 없음

실제 Unity 6000.3.15f1 의 `UnityEngine.CoreModule.dll` **메타데이터를 직접 읽어** 확정했습니다.

```
UnityEngine.Events.PersistentListenerMode
   EventDefined = 0   ← 목록 위쪽 Dynamic
   Void = 1 · Object = 2 · Int = 3 · Float = 4 · String = 5 · Bool = 6
```

직렬화 구조는 **실제 씬 파일**(`Samples/.../DemoScene.unity`)에서 확인했습니다.

```yaml
m_PersistentCalls:
  m_Calls:
  - m_Target: {fileID: ...}
    m_MethodName: SetActive
    m_Mode: 6            ← Bool. 메타데이터에서 읽은 값과 일치
```

→ 경로 `<이벤트칸이름>.m_PersistentCalls.m_Calls` · 하위 `m_Target` · `m_MethodName` · `m_Mode` **전부 맞습니다.**

#### 7-1-2. ✅ 에디터에서 실측했습니다 (2026-08-23)

`Tools ▸ 교안 씬 빌더 ▸ 기반 자체 시험` 을 돌려 **12개 항목 전부 통과**했습니다.
코드로 실제로 연결을 걸고, 걸린 결과를 되읽은 값입니다.

| 연결한 방식 | 되읽은 `m_Mode` | |
| :--- | :---: | :--- |
| 인자 없는 동작 (`MouseLook.LockCursor`) | **0** | |
| **값을 넘기는 연결** (`ValueDisplay.SetValue`) | **0** | ✅ **Dynamic** |
| 정해둔 참/거짓 (`GameObject.SetActive`) | **6** | Bool |

> 💡 **인자 없는 동작도 `0` 이 나옵니다**
>
> 점검기는 **`UnityEvent<T>` 인 칸에서만** `m_Mode != 0` 을 지적하므로 서로 부딪히지 않습니다.
> 인자 없는 칸은 애초에 검사 대상이 아닙니다.

#### 7-2. asmdef 는 만들지 않았습니다

| | |
| :--- | :--- |
| 이유 | asmdef 를 붙인 에디터 어셈블리는 **기본 어셈블리(`Assembly-CSharp`)를 참조할 수 없습니다** |
| 그런데 | `SimpleGun` 등 22개 부품이 전부 기본 어셈블리에 있습니다 |
| 그러면 | 런타임 스크립트에도 asmdef 를 붙여야 하는데, **수강생 프로젝트 구조가 바뀝니다** |
| 결론 | **`Editor/` 폴더 규칙만으로 충분합니다.** 폴더 이름이 `Editor` 면 빌드에 안 들어갑니다 |

#### 7-3. 부품 식별 방법

22개 부품이 **전부 `AddComponentMenu("NoCode Kit/...")` 를 갖고 있습니다.** 이걸로 식별합니다.
이름에 의존하지 않으므로 수강생이 오브젝트 이름을 어떻게 짓든 상관없습니다.

#### 7-4. "반드시 채워야 하는 칸" 의 근거

임의로 정하지 않았습니다. **부품이 스스로 `Debug.LogWarning` 을 내는 칸만** 넣었습니다.

| 부품 | 필수 칸 |
| :--- | :--- |
| `SimpleGun` | `Bullet Prefab` |
| `TargetLauncher` | `Target Prefab` |
| `FeedbackSpawner` | `Effect Prefab` |
| `DifficultyPreset` | `Launcher` · `Timer` |

> 💡 **부품이 이미 알려주고 있는데 왜 또 하나요**
>
> 그 경고는 **▶ 를 누르고 그 상황이 실제로 벌어져야** 나옵니다.
> `SimpleGun` 은 **총을 쏴야** 알려주고, `FeedbackSpawner` 는 **맞혀야** 알려줍니다.
> 점검기는 **▶ 를 누르기 전에** 알려줍니다.

#### 7-5. 재료함의 틀(Prefab)도 봅니다

표적·총알의 `Hittable` · `Projectile` 은 **씬이 아니라 틀 안에** 있습니다.
작업대만 보면 25차시 실습을 통째로 놓치므로, `Assets/` 아래 틀도 같이 훑습니다.
