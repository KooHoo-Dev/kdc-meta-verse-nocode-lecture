## 2. 폴더 구조

```
Assets/
├── _NoCodeKit/                  ← 수강생 배포 대상 (언더바로 최상단 고정)
│   ├── Scripts/                 교육용 컴포넌트 (수강생은 열지 않음)
│   ├── Prefabs/
│   ├── Materials/
│   ├── Audio/
│   └── VFX/
├── _Lectures/                   ← 차시별 씬
│   ├── 13_EditorTour.unity
│   ├── 14_Basics.unity
│   └── ...
├── _ClayShooting/               ← 22~27 클레이 사격 전용
│   ├── Prefabs/
│   ├── Scenes/
│   └── Milestones/              차시별 완료 상태 씬 (진도 복구용)
├── _XR/                         ← 28~33 XR 전용
└── Settings/                    (기존 URP 설정 유지)
```

- 수강생이 만드는 것은 `Assets/` 바로 아래에 두게 안내합니다. **강의 자산과 본인 작업물을 섞지 않는 것**이 15차시(데이터 관리) 실습의 일부입니다.
- `_NoCodeKit/Scripts/` 는 수강생이 **열어볼 일이 없어야** 합니다. 각 차시 "코드 딱 한 번 보기"에서만 강사가 엽니다.

## 3. 교육용 컴포넌트 명세

### 3-0. 설계 제약 (전 컴포넌트 공통)

노코드 실습이 성립하려면 아래를 지켜야 합니다.

| 규칙 | 이유 |
| :--- | :--- |
| 버튼에 걸 동작은 **`public void` + 매개변수 없음** | 매개변수가 있으면 `On Click` 드롭다운에서 고르기 어려움. 단일 `float`/`int`/`string`/`bool` 까지만 허용 |
| 조절값은 **`[Header]` 로 묶고 `[Tooltip]` 부착** | 교안의 "조절할 수 있는 값" 표와 1:1 대응돼야 함 |
| 이벤트는 **`public UnityEvent`** | Inspector에 `On Click` 과 똑같이 생긴 칸으로 나와야 함 |
| **Inspector 표시명이 곧 교안 용어** | `rotationSpeed` → `Rotation Speed`. 교안 표와 글자까지 일치시킬 것 |
| 실행 중 값 변경이 **즉시 반영** | 실습 ②(값 조작)의 전제 |
| 참조는 **비어 있어도 오류로 죽지 않게** | 수강생이 칸을 안 채우고 Play를 누름. 빨간 오류 대신 노란 경고 1줄 |

## 6. 배포 방식

| 배포물 | 형태 | 갱신 시점 |
| :--- | :--- | :--- |
| **`NoCodeKit.unitypackage`** | 교육용 컴포넌트 + 공용 재질 + TMP 한글 폰트 | Batch 완료마다 누적 갱신 |
| **차시 시작 씬** | 차시별 `.unitypackage` | 해당 차시 확정 시 |
| **클레이 사격 마일스톤** | 22~27 완료 상태 6개 | Batch C 완료 시 |
| **VR 프로젝트 설정 가이드** | 문서 (28차시 교안에 통합) | Batch D |

- 수강생 안내는 **"Project 창에 끌어다 놓기"** 한 가지로 통일합니다. 15차시에서 배우는 방식 그대로입니다.
- `.unitypackage` 는 리포지토리에 커밋하지 않습니다 (용량). **GitHub Releases 또는 별도 배포처**를 사용하고, 교안에서는 "강의자료" 로만 지칭합니다.

## 7. 클레이 사격 제작 방식 — 역분할

교안 6차시가 프로젝트에 묶여 있으므로, 순서를 뒤집습니다.

```
1) 게임을 끝까지 한 번 완성한다 (코드 유무 신경 쓰지 않고)
        ↓
2) 완성본을 6개 마일스톤으로 역분할한다
        ↓
3) 각 마일스톤 사이의 차이 = 그 차시의 실습 ③
        ↓
4) 그 차이를 만들어내는 조작이 마우스만으로 되는지 검증한다
        ↓  안 되면
5) 부족한 부분을 교육용 컴포넌트로 흡수한다
        ↓
6) 교안 집필
```

| 마일스톤 | 차시 | 그 시점의 상태 |
| :---: | :---: | :--- |
| M1 | 22 | 걸어 다닐 수 있는 빈 사격장 |
| M2 | 23 | 표적이 날아옴 (아직 못 맞힘) |
| M3 | 24 | 총알이 나감 (아직 안 맞음) |
| M4 | 25 | 맞으면 터지고 점수가 오름 — **게임 성립** |
| M5 | 26 | 난이도 3단계 |
| M6 | 27 | 배경·조명·소리가 붙은 완성본 |

> **4단계 검증이 핵심입니다.** "이 조작이 마우스만으로 되는가"를 통과하지 못하면 그 실습은 성립하지 않습니다. 통과 못 하는 부분이 곧 새 교육용 컴포넌트의 명세가 됩니다.

## 9. 검증 항목

각 컴포넌트를 만들 때 아래를 확인합니다.

- [ ] Inspector 표시명이 **교안 표의 글자와 일치**하는가
- [ ] 버튼 `On Click` 드롭다운에 동작이 **전부 보이는가**
- [ ] 참조 칸을 **비운 채로 Play** 해도 빨간 오류로 죽지 않는가
- [ ] Play 중에 값을 바꾸면 **즉시 반영**되는가
- [ ] 부품을 **체크 해제**하면 동작이 멈추는가 (1차시 "붙이면 생기고 빼면 사라진다"의 근거)
- [ ] 프리팹을 씬에 **여러 개 놓아도** 각자 독립 동작하는가
- [ ] `_NoCodeKit` 만 임포트한 **빈 프로젝트에서도** 동작하는가
