# 갈래 A 씬 정리 계획 — 쌓이는 것을 어떻게 접을까

> 13 ~ 21차시 완성 씬이 **아홉 차시치를 전부 안고 있어** 가시성이 떨어지는 문제.
> 무엇이 진짜 필요하고 무엇이 관성인지 가려내고, 정리 방법을 정합니다.
> 작성: 2026-08-24

---

## 1. 결론부터

> ✅ **3D 는 괜찮습니다. 문제는 화면(UI) 입니다.**
>
> 3D 는 `BuildBasicsLayout` 이 **자리를 나눠뒀고** 차시마다 **카메라가 주인공을 잡습니다.**
> 그런데 **화면 요소는 겹칠 자리가 없습니다.** 전부 같은 판 위에 올라갑니다.

21차시 완성 씬의 `Canvas` 자식은 **열일곱 개**입니다.

| 차시 | 화면에 올린 것 | 개수 |
| :---: | :--- | :---: |
| 14 | `StopButton` · `StartButton` | 2 |
| 16 | 입체 · 그림 · 효과 · 끄기 | 4 |
| 17 | `DemoImage` · `HealthBar` · `ScoreBox` · `TopBar` · `BottomBar` | 5 |
| 18 | `ColorButton` · `Slider` (+ `ScoreText`) | 2 |
| 19 | `ControlPanel` (버튼 3) | 1 |
| 20 | `DrivePanel` (버튼 7) · `InfoText` | 2 |
| | **합계** | **16 + 1** |

**버튼만 세면 열여섯 개**가 한 화면에 있습니다.

---

## 2. 무엇이 진짜 필요한가 — 의존 관계를 전부 훑었습니다

교안에서 **뒤 차시가 이름을 대며 쓰는 것**만 추렸습니다.

| 오브젝트 | 만든 차시 | 뒤에서 쓰나 | 근거 |
| :--- | :---: | :---: | :--- |
| **`Car`** | 14 | ✅ **15 · 19** | 15차시 *"지난 시간에 만든 자동차"* · 19차시 *"14차시에 만든 자동차"* |
| **`HealthBar`** | 17 | ✅ **18** | 18차시 실습 ④ 1번 *"17차시에 만든 `HealthBar` 를 선택합니다"* |
| **`ScoreBox`** | 17 | ✅ **18** | 18차시 실습 ② 1번 *"17차시에 만든 `ScoreBox` 위에서 우클릭"* |
| `ColorButton` | 18 | △ **19** | 19차시 실습 ① — *"버튼을 눌러봅니다"*. **아무 버튼이나 되지만 색 변화가 커서 제일 잘 보입니다** |
| `ControlPanel` | 19 | △ **20** | 20차시 실습 ③ 3번. 단 **씬 오브젝트가 아니라 «틀»** 을 씁니다 |
| `Cube` (13) | 13 | ❌ | 재료(`RedMat`)는 15차시가 쓰지만 그건 **재료함에 있는 파일**입니다 |
| `StopButton` · `StartButton` | 14 | ❌ | 19차시가 **같은 기능의 패널을 새로** 만듭니다 |
| `Car (1)` ~ `Car (4)` | 15 | ❌ | 15차시의 «다섯 대» 데모 자체 |
| `Display` + 자식 3 · 모드 버튼 4 | 16 | ❌ | |
| `DemoImage` · `TopBar` · `BottomBar` | 17 | ❌ | |
| `ScoreText` · `Slider` | 18 | ❌ | |
| `DriveCube` · `DrivePanel` · `InfoText` | 20 | ❌ | |

> 🚨 **진짜 필수 연결은 셋뿐입니다**
>
> **`Car`(14 → 15 · 19)** · **`HealthBar`(17 → 18)** · **`ScoreBox`(17 → 18)**.
>
> 나머지는 **«지우라는 말이 없어서 남아 있는 것»** 입니다. 필요해서가 아닙니다.

### 다만 교안이 «함께 쓴다»고 써둔 곳이 둘 있습니다

| 차시 | 원문 | 실제로 필요한 것 |
| :---: | :--- | :--- |
| **19** | *"**14차시에 만든 자동차**와 **17 · 18차시에 만든 화면**을 함께 씁니다"* | 자동차 ✅ / «화면» 은 **눌릴 버튼 하나**면 성립 |
| **20** | *"19차시에 만든 **조작 패널을 그대로 재활용**합니다"* | **틀(Prefab)** 이면 됨. 씬에 남아 있을 필요 없음 |

**앞서 `plans/10` 에서 *"꺼두면 19 · 20차시 실습이 성립하지 않는다"* 고 썼는데, 그건 «전부 끄자» 를 두고 한 말입니다.**
지금 제안은 **«그 차시가 안 쓰는 화면 요소만»** 접는 것이라 다릅니다. 자동차는 계속 켜둡니다.

## 3. 방법 세 가지

| | 무엇 | 장점 | 단점 |
| :---: | :--- | :--- | :--- |
| **A** | **차시별 묶음으로 접기** — `Canvas` 아래 차시 그릇을 두고 안 쓰는 묶음은 **체크 해제** | Hierarchy 도 화면도 정리됨 · **지우는 게 아니라 접는 것**이라 켜면 다 있음 | 수강생 씬은 켜져 있어 **완성 씬과 한 끗 다름** |
| **B** | **교안에 «지난 차시 정리» 단계 추가** | 수강생 씬도 같이 깨끗해짐 | **교안 7곳 수정** · 차시마다 정리 단계가 붙어 흐름이 끊김 |
| **C** | 그대로 두고 카메라 · 스크린샷으로만 대응 | 손댈 게 없음 | **지금 상태.** 화면 요소는 카메라로 못 가립니다 |

> ✅ **추천 — A**
>
> **B 는 교안이 가르치려는 것과 어긋납니다.** 이 강의는 *"쌓아 올린다"* 가 설계고,
> 19차시가 *"14차시 자동차를 씁니다"* 라고 말하는 것 자체가 성취감 장치입니다.
> 거기에 «지우세요» 를 끼워 넣으면 그 맛이 사라집니다.
>
> **A 는 «지우기» 가 아니라 «접기»** 입니다.
> Hierarchy 에는 그대로 있고, 체크 한 번이면 되돌아옵니다.
> 완성 씬은 **그 차시 결과 화면**이 되고, 정답지로서도 «다 들어 있다» 가 유지됩니다.

## 4. A 안 설계

### 4-1. 묶음 구조

```
Canvas
├── 14차시 조작          StopButton · StartButton
├── 16차시 갈아 끼우기    입체 · 그림 · 효과 · 끄기
├── 17차시 화면 틀        DemoImage · TopBar · BottomBar
├── HealthBar            ← 묶지 않습니다. 18차시가 이어서 씁니다
├── ScoreBox             ← 〃 (ScoreText 를 자식으로 받습니다)
├── 18차시 버튼과 슬라이더  ColorButton · Slider
├── 19차시 조작 패널       ControlPanel
└── 20차시 조작 패널       DrivePanel · InfoText
```

> 📝 **`HealthBar` · `ScoreBox` 는 왜 안 묶나**
>
> 교안이 **18차시에서 이름을 대며 찾습니다.** 묶음 안에 들어가면
> *"17차시에 만든 `ScoreBox` 위에서 우클릭"* 을 따라오는 수강생이 **한 겹 더 헤매게** 됩니다.
>
> 그리고 이 둘은 **17차시부터 끝까지 켜져 있어도 방해가 안 됩니다.** 화면 모서리에 붙어 있어서요.

### 4-2. 차시마다 무엇을 켤까

**규칙 — «그 차시에 만든 것» + «그 차시 교안이 이름을 대며 쓰는 것».**

| 차시 | 켜는 묶음 | 왜 |
| :---: | :--- | :--- |
| **14** | 14 | |
| **15** | 14 | 자동차를 멈춰두고 다섯 대를 놓는 차시. 그 버튼이 필요합니다 |
| **16** | 14 · 16 | 17차시 교안 — *"14 · 16차시에 맛보기로 써본 버튼"*. 나란히 있어야 그 말이 삽니다 |
| **17** | 17 · HUD | 14 · 16 을 **접습니다.** 오늘은 앵커가 주인공입니다 |
| **18** | 17 · HUD · 18 | 교안 — *"17차시에 만든 화면 틀을 그대로 씁니다"* |
| **19** | HUD · 18 · 19 | 실습 ①이 «버튼이 안 눌린다» 를 봐야 해서 `ColorButton` 을 켜둡니다. **17차시 장식은 접습니다** |
| **20** | 19 · 20 | 교안 — *"19차시에 만든 조작 패널을 그대로 재활용"*. **둘을 나란히** 두면 그 말이 보입니다 |
| **21** | 19 · 20 | 21차시는 화면 요소를 안 만듭니다. 20차시 상태 그대로 |

**최대 세 묶음.** 지금 여섯 묶음이 한꺼번에 떠 있는 것과 견주면 확 줄어듭니다.

### 4-3. 3D 는 손대지 않습니다

| | |
| :--- | :--- |
| **왜** | 자리를 이미 나눠뒀고, 차시마다 **카메라가 주인공을 잡습니다.** 실제로 읽힙니다 |
| **묶으면 오히려 나쁩니다** | `Car` 를 그릇에 넣으면 14차시의 *"부모가 돌면 자식이 따라 돈다"* 와 **겹쳐서 헷갈립니다** |
| **15차시 자동차 넷은 두는 게 낫습니다** | 19차시에서 **한 대만 파래지는** 대조군이 됩니다 |

## 5. 할 일

| 순서 | 무엇 | 파일 |
| :---: | :--- | :--- |
| 1 | `BuildKitUi` 에 **묶음 그릇 만들기 · 접기** 도우미 추가 | `BuildKitUi.cs` |
| 2 | 묶음 이름과 «차시별로 무엇을 켜나» 표를 배치표에 | `BuildBasicsLayout.cs` |
| 3 | 14 · 16 · 17 · 18 · 19 · 20차시 빌더가 **자기 묶음 안에** 화면 요소를 만들게 | 빌더 6개 |
| 4 | 각 빌더 끝에서 **그 차시 규칙대로 켜고 끄기** | 빌더 8개 (`13` 제외) |
| 5 | 자체 시험에 «묶음이 만들어지고 접히는지» 항목 추가 | `BuildKitSelfTest.cs` |
| 6 | 교안 «이 자료는 이렇게 보세요» 에 **한 줄** — 지난 차시 화면 요소는 접어둘 수 있다 | 교안 8곳 (한 줄씩) |

> ⚠️ **6번은 선택입니다**
>
> 안 넣어도 됩니다. 수강생 씬은 전부 켜져 있을 텐데, **그게 틀린 건 아닙니다.**
> 다만 *"내 화면은 왜 이렇게 복잡하지?"* 를 미리 풀어주는 한 줄이라 있으면 좋습니다.

**최대 두 묶음.** `HealthBar` · `ScoreBox` 는 묶음 밖이라 17차시부터 늘 켜져 있습니다.

> 📝 **자체 시험에 «접힌 뒤 다시 찾기» 를 넣은 이유**
>
> 17차시가 14차시 묶음을 접은 뒤에도, **뒤 차시 빌더가 그 묶음을 다시 잡아야** 합니다.
> `Transform.Find` 는 꺼진 자식도 찾지만 `GameObject.Find` 는 **못 찾습니다.**
> 묶음은 반드시 `Transform.Find` 쪽으로 다루도록 시험이 지켜봅니다.
