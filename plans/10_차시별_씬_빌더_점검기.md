# 차시별 씬 · 빌더 · 점검기 대응표

> 13 ~ 33차시의 **완성 씬을 코드로 만들고**, 각 차시를 **점검기로 확인**하기 위한 대응표입니다.
> 설계 배경은 `plans/09_에디터_도구_작업계획.md` 에 있습니다.
> 작성: 2026-08-23

## 1. 씬은 차시마다 하나씩 (1:1)

**모든 차시가 자기 씬 파일을 갖습니다.** 만드는 방법은 하나뿐입니다.

```
이전 차시 완성 씬을 복제  →  NN_시작 으로 저장  →  이번 차시 것만 얹기  →  NN_완성 으로 저장
```

이렇게 하면 세 가지가 한꺼번에 해결됩니다.

| | |
| :--- | :--- |
| **차시별 차이가 보입니다** | `NN_시작` ↔ `NN_완성` 을 견주면 **그 차시가 무엇을 더했는지** 정확히 나옵니다 |
| **놓친 수강생이 붙습니다** | `NN_시작` 을 열면 그 차시부터 다시 시작할 수 있습니다 |
| **강사에게 정답지가 생깁니다** | `NN_완성` 이 그 차시의 결과 화면입니다 |

### 시작 씬은 어디서 오나

| 차시 | `NN_시작` 의 출처 |
| :---: | :--- |
| **13** | 빈 씬 |
| 14 ~ 21 | 이전 차시 완성 |
| **22** | **빈 씬** — 교안이 `New Scene` 이라고 말합니다 |
| 23 ~ 27 | 이전 차시 완성 |
| **28** | **빈 씬** — 〃 |
| 29 ~ 31 | 이전 차시 완성 |
| **32** | **`27_완성`** — 31차시가 그렇게 예고해뒀습니다 |
| **33** | 32차시 완성 |

**21차시 × 2 = 42개 파일.** 빌더가 만드니 손이 안 갑니다.

> ⚠️ **앞 판본에서 제가 틀린 것 — 안 쓰는 걸 꺼두자고 했는데, 그러면 교안이 깨집니다**
>
> | 차시 | 교안 원문 |
> | :---: | :--- |
> | **19** | *"**14차시에 만든 자동차**와 **17 · 18차시에 만든 화면**을 함께 씁니다"* |
> | **20** | *"19차시에 만든 **조작 패널을 재활용**해서"* |
>
> **쌓이는 게 이 강의의 설계입니다.** 꺼두면 19 · 20차시 실습이 성립하지 않습니다.
>
> 화면이 산만한 문제는 **카메라 앵글**로 풉니다.
> 완성 씬마다 카메라를 그 차시 결과물 쪽으로 맞추면 스크린샷이 그 차시를 보여줍니다.
> **씬 내용은 건드리지 않습니다.**

> 📝 **이 판단을 `plans/13` 이 한 번 더 좁혔습니다** (2026-08-24)
>
> 위 글은 **«전부 끄자»** 를 두고 한 말입니다. 그건 여전히 안 됩니다.
>
> 그런데 갈래 A를 실제로 만들어보니 **카메라만으로는 화면 요소를 못 가립니다.**

>
> → **3D 는 그대로, «그 차시가 안 쓰는 화면 요소만» 접습니다.**

| | |
| :--- | :--- |
| 씬 파일 | `Assets/_NoCodeKit/Scenes/**NN/**NN_시작.unity` · `NN_완성.unity` — **차시 폴더 아래 짝으로** |
| 틀(Prefab) | `Assets/_NoCodeKit/Scenes/**NN/Prefabs/**` — **차시 폴더 안에** |
| 재질 | `Assets/_NoCodeKit/Materials/` — **나누지 않습니다** (아래 참고) |
| 빌더 | `Assets/_SceneBuilder/Editor/BuildNN○○○.cs` — **배포 안 함** |
| 점검기 | `Assets/_NoCodeKit/Editor/Lessons/CheckNN○○○.cs` — **배포함** |
| 빌더 메뉴 | `Tools ▸ 교안 씬 빌더 ▸ NN차시` |
| 점검기 메뉴 | `Tools ▸ 노코드 점검 ▸ NN차시 확인` |

> ✅ **`NN_시작` 은 이미 교안이 그렇게 쓰고 있습니다**
>
> 23 · 29 · 30 · 31 · 32차시에서 **9곳**이 `NN_시작` 으로 통일돼 있습니다. 그대로 갑니다.

> ✅ **완성 씬 이름을 `NN_완성` 으로 통일했습니다** (2026-08-24)
>
> | 고친 것 | 몇 곳 | 어디 |
> | :--- | :---: | :--- |
> | `22_완료` ~ `26_완료` → `NN_완성` | **7** | 22 ~ 26차시 (교안 5 + VOD 2) |
> | `28_VR연습` → `28_완성` | **9** | 28 · 29차시 (교안 4 + VOD 5) |
> | `27_완성` | 4 | 처음부터 맞았습니다 |
>
> 이제 교안·VOD 전체가 **`NN_시작` · `NN_완성` 한 쌍**으로 통일돼 있습니다.

> 📝 **틀은 나누고, 재질은 안 나눕니다**
>
> | | 왜 |
> | :--- | :--- |
> | **틀은 차시 폴더 안에** | **어느 차시가 무엇을 만들었는지** 폴더만 봐도 보입니다. 접시 틀은 23차시, 총알 틀은 24차시 |
> | **재질은 한곳에** | 색은 여러 차시가 같이 씁니다. 나누면 같은 색이 여러 벌 생깁니다 |
>
> 틀이 23차시 폴더에 있어도 **24 ~ 27차시가 그대로 씁니다.**
> 유니티는 경로가 아니라 고유 ID로 찾아가기 때문에, 폴더가 어디든 상관없습니다.

> ⚠️ **앞 차시를 다시 만들면 뒤 차시도 다시 만들어야 합니다**
>
> 25차시가 **23차시의 접시 틀에** `Hittable` 을 붙입니다.
> 그런데 23차시를 다시 돌리면 접시 틀이 **처음 상태로 새로 만들어집니다.**
>
> → `Hittable` 이 사라져서 **이미 만들어둔 25 ~ 27차시 씬이 깨집니다.**
> **앞 차시를 고쳤으면 그 뒤를 차례로 다시 돌려주세요.**

> 🚨 **틀에서 찍어낸 것을 코드로 고칠 때 — 반드시 «다른 부분»으로 기록해야 합니다** (2026-08-24)
>
> 29차시에서 눈높이를 **`1.6`** 으로 넣고 저장했는데,
> 열어보니 **틀의 기본값 `1.36144`** 로 되돌아가 있었습니다.
>
> C# 으로 값을 대입하면 **메모리에서만 바뀝니다.**
> 틀에서 찍어낸 것은 «틀과 뭐가 다른지» 목록으로 저장되는데,
> 대입만으로는 **그 목록에 안 올라갑니다.** `EditorUtility.SetDirty` 로도 부족합니다.
>
> → **`BuildKit.RecordPrefabChange(component)`** 를 부르세요.
> 틀이 아닌 것에 불러도 안전합니다 (그냥 «바뀌었다» 표시만 합니다).
>
> **갈래 C 가 특히 위험합니다.** XR Origin · Simulator 가 전부 XRI 샘플 틀에서 나온 것이라서요.

> 🚨 **유니티 물건에 `??` · `?.` 를 쓰면 안 됩니다** (2026-08-24)
>
> ```
> var box = go.GetComponent<BoxCollider>() ?? go.AddComponent<BoxCollider>();   // ❌
> ```
>
> 유니티는 **«없는 부품» 을 null 처럼 보이게 하려고 `==` 를 다시 만들어뒀습니다.**
> 그런데 **`??` 와 `?.` 는 그 `==` 를 건너뛰고** C# 의 진짜 null 만 봅니다.
>
> 그래서 «없는 부품» 을 **있다고 판단해 그대로 돌려주고**,
> 값을 넣는 순간 **`MissingComponentException`** 으로 터집니다. 32차시 빌더에서 실제로 겪었습니다.
>
> → **`BuildKit.Ensure<T>(go)`** 와 **`BuildKit.EnsureEmpty(name)`** 를 쓰세요.
> 직접 쓸 때는 반드시 **`== null` 로 물어봐야** 합니다.

> 📝 **시작 씬과 완성 씬은 쓰임이 다릅니다**
>
> | | 누가 쓰나 |
> | :--- | :--- |
> | **`NN_시작`** | **수강생.** 진도를 놓쳤거나 자기 것이 망가졌을 때 여기서 다시 붙습니다 |
> | **`NN_완성`** | **강사 · 수강생.** 정답지이자 그 차시의 결과 화면입니다 |
>
> 내용은 **`NN_시작` = `(NN-1)_완성`** 으로 같습니다. 그래도 파일을 따로 두는 이유는
> *"30차시를 시작하려면 `30_시작` 을 여세요"* 가 *"`29_완성` 을 여세요"* 보다 **훨씬 덜 헷갈리기** 때문입니다.

## 4. 차시별 핵심 점검 항목

점검기가 **그 차시에 대해** 확인할 것입니다. 상시 점검(빈 칸 · 끊어진 연결 · Dynamic/Static · 이름표)은 **모든 차시에 항상** 돕니다.

> ⚠️ **이름으로 찾지 않습니다**
>
> 수강생이 `Gun` 대신 `총` 이라 지어도 통과해야 합니다. **전부 부품 기준**으로 씁니다. (`plans/09` §4-2)

| 차시 | 핵심 점검 |
| :---: | :--- |
| 13 | 색깔 재료가 **하나 이상 만들어졌고**, 어떤 물건에 **입혀져 있는지** |
| 14 | `CubeSpinner` 가 있고 · **자식이 4개 이상인 묶음**이 있고 · 버튼 `On Click` 에 **연결이 있는지** |
| 15 | 씬에 **같은 틀에서 나온 것이 여럿** 놓였는지 |
| 16 | `RendererSwitcher` 가 있고 · **세 칸 중 둘 이상**이 채워졌는지 |
| 17 | `Canvas` 가 있고 · 자식이 **가운데 앵커가 아닌 것**이 있는지 (앵커를 만졌는지) |
| 18 | `Slider` 의 `On Value Changed` ▸ `ValueDisplay.SetValue` 가 **`Dynamic float`** 인지 ★ |
| 19 | `EventSystem` 이 **있는지** · 버튼 `On Click` 대상이 **끊어지지 않았는지** |
| 20 | `TransformDriver` 가 있고 · 버튼이 **셋 이상** 연결됐는지 |
| 21 | `Rigidbody` 와 `Collider` 가 같이 있는지 · `CollisionReporter` 의 이름표가 **등록됐는지** |
| 22 | `PlayerMover` 에 `Rigidbody` 가 있고 **`Freeze Rotation` 이 켜졌는지** · `MouseLook` 의 **조상에 Camera** |

## 7. 빌더를 쓰다 밟은 함정

씬을 만들면서 **실제로 두 번 이상 틀렸던 것들**입니다. 다음에 또 밟지 않으려고 적어둡니다.

### 함정 ① — `??` 와 `?.` 는 Unity 물건에 쓰면 안 됩니다

Unity 는 `==` 를 자기 방식으로 다시 정의해뒀습니다. **지워진 물건도 «없음» 으로 보이게** 하려고요.
그런데 `??` 와 `?.` 는 **그 정의를 건너뜁니다.** 그래서 이미 지워진 부품을 «있다» 고 판단하고,
그 다음 줄에서 `MissingComponentException` 이 터집니다.

→ `BuildKit.Ensure<T>(go)` · `BuildKit.EnsureEmpty(name)` 을 쓰세요.

### 함정 ② — 틀에서 찍어낸 것은 값을 바꿔도 저장되지 않습니다

`instance.field = 3;` 은 **씬에 기록되지 않습니다.** 틀(프리팹)에서 온 물건이라
«원래 값과 다르다» 는 표시를 따로 남겨줘야 합니다.

→ `BuildKit.RecordPrefabChange(component)` 또는 `SerializedObject` + `ApplyModifiedProperties`.
`XR Origin` 의 키 높이(`1.6`)가 **두 번이나 안 바뀐 이유**가 이것이었습니다.

### 함정 ③ — 상호작용 이름표는 «있어야» 고를 수 있습니다

교안이 *"목록에서 `Teleport` 를 고르세요"* 라고 해도, 프로젝트에 그 이름표가 **없으면 목록에 안 뜹니다.**
기본값은 `Default` 하나뿐입니다.

→ `BuildKit.EnsureInteractionLayer(name)` 로 **먼저 만들고** 번호로 지정하세요.

### 함정 ④ — 세상 글자·화면은 «+Z 가 보는 방향» 입니다

**세 번 틀렸습니다.** `TextMeshPro`(세상 글자)와 `World Space` 화면은
**`+Z` 가 향하는 쪽이 «앞면» 이 아닙니다.** `+Z` 는 **보는 사람이 바라보는 방향**입니다.

| 판의 `+Z` 가 | 결과 |
| :--- | :--- |
| 사람 쪽을 향함 | ❌ 좌우로 **뒤집혀** 보임 |
| 사람 반대쪽 (= 사람이 보는 방향) | ✅ 바로 읽힘 |

그래서 `Quaternion.LookRotation(판 − 사람)` 입니다. **`사람 − 판` 이 아닙니다.**
그리고 판이 그렇게 서면 **자식(버튼·글자)은 부모 기준 `−Z`** 로 튀어나와야 사람 앞에 옵니다.

> 곁들여 — **눌린 부모 안에 글자를 넣지 마세요.**
> `0.44 × 0.2` 처럼 납작한 큐브의 자식이 되면 글자도 같이 눌립니다.
> «역수 크기» 로 되돌리려 하면 **회전과 겹쳐 뒤집힙니다.** 글자는 **형제**로 두세요.

### 함정 ⑤ — 리그에는 부딪히는 몸이 없습니다

XRI 리그(`XR Origin`)의 손에는 **`Collider` 가 하나도 없습니다.**
그래서 3D 버튼에 **손을 대기만 해서는 절대 안 눌립니다.** 반드시 `G`(select)여야 합니다.

교안·스크립트 양쪽에 **육성 경고**로 넣어두었습니다. 안 넣으면 질문 1위가 됩니다.

### 함정 ⑥ — heredoc 안의 `\n` 은 진짜 줄바꿈이 됩니다

C# 글자 안에 `\n` 이 들어간 줄을 heredoc 으로 고치면 **그 자리에서 줄이 끊겨** 빌드가 깨집니다.

→ 그런 줄은 **Edit 도구로** 고치거나, `\n` 이 없는 부분만 골라 바꾸세요.
