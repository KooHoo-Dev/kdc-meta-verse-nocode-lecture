>
> 작업실에는 뭐가 있죠? 우선 **작업대**가 있습니다. 직접 만지고 조립하는 공간이요. Unity에서는 **Scene**입니다.
> 그리고 **손님 눈에 어떻게 보이는지 확인하는 거울**이 있습니다. 그게 **Game**이에요.

> 재료를 넣어두는 **재료함**이 있겠죠. **Project**입니다.

> 고른 물건을 세밀하게 조정하는 **설정판**이 **Inspector**입니다. 지난 시간에 계속 쓰셨던 그 창이죠.

>
> 지금 이름을 외우려고 하지 마세요. **어차피 손으로 만지다 보면 외워집니다.**

# **[00:07 ~ 00:14] 창 여섯 개 — 직접 열고 닫아봅니다**

✂️ **구분 자막**: `① 작업실 둘러보기`

🖥 **화면 전환**: **Unity Editor로 전환**

## **창 하나씩 짚어주기 (00:07 ~ 00:11)**

🗣
> "지금 이게 실제 Unity 화면입니다. 지난 시간에 복잡하다고 하셨던 그 화면이에요.
> 이제 하나씩 짚어보겠습니다."

**1. Hierarchy — 왼쪽**

🗣
> "왼쪽이 **Hierarchy**. **지금 작업대 위에 뭐가 있는지 적어둔 목록**입니다.
> 여기서 우클릭하면 새 물건을 만들 수 있어요. 지난 시간에 빈 그릇 만들 때 쓰셨죠."

**2. Scene / Game — 가운데**

🗣
> "가운데에 이름표가 두 개 붙어 있습니다. **Scene**과 **Game**이요.
> 지금은 Scene이 켜져 있습니다. **작업대**예요.
>
> 옆의 Game을 눌러보겠습니다. **화면이 확 달라지죠?**
> 이 두 개가 왜 다른지는 **잠시 후에 아주 자세히** 다루겠습니다. 오늘의 핵심이라서요."

**3. Inspector — 오른쪽**

🗣
> "오른쪽이 **Inspector**입니다. 지난 시간 내내 쓰셨던 그 조종석이에요.
> 물건을 하나 고르면, 여기에 그 물건의 부품 목록이 쭉 나옵니다."

**4. Project / Console — 아래쪽**

🗣
> "아래쪽에 이름표가 또 두 개 있습니다. **Project**와 **Console**이에요.
>
> **Project는 재료함**입니다. 프로젝트에 들어 있는 파일이 전부 여기 있어요.
> 지난 시간에 큐브에 붙였던 그 부품 파일도 여기 들어 있습니다.
>
> **Console은 메모장**입니다. Unity가 여러분한테 할 말이 있을 때 여기에 적어둡니다."

**5. Project와 Hierarchy 구분** — 두 창을 번갈아 클릭

🗣
> "여기서 하나 짚고 갈게요. **Project와 Hierarchy를 헷갈리는 분이 많습니다.**
>
> **Project는 재료함에 보관 중인 것**입니다. 아직 화면에 안 나와요.
> **Hierarchy는 작업대 위에 실제로 올려둔 것**입니다. 화면에 나옵니다.
>
> 재료함에서 꺼내서 작업대에 올리는 게 **끌어다 놓기**고요. 이따 직접 해보십니다."

**6. 창 닫았다가 되살리기** — Console 탭 우클릭 → Close Tab → Window → General → Console

🗣
> "그리고 아주 중요한 걸 알려드리겠습니다. **창을 일부러 하나 닫아보겠습니다.**
>
> Console 이름표에서 오른쪽 클릭하고, Close Tab. **사라졌습니다.**
>
> 이거, 작업하다 보면 **반드시 겪습니다.** 저도 겪고요. 그런데 되찾는 법만 알면 아무 일도 아니에요.
> 위쪽 **Window** 메뉴, **General**, **Console**. **돌아왔습니다.**"

**7. 배치 통째로 복구** — 탭 아무거나 드래그해서 흐트러뜨린 뒤 Window → Layouts → Default

🗣
> "이번엔 배치를 아예 망가뜨려 보겠습니다. 이름표를 잡고 아무 데나 끌어다 놓습니다. 엉망이 됐죠?
>
> **Window, Layouts, Default.** 한 번에 원래대로 돌아옵니다.
>
> **이 메뉴 하나만 기억하시면 화면이 어떻게 망가져도 괜찮습니다.**"

## **⏸ 실습 ① (00:11 ~ 00:14)**

🗣
> "자, 직접 해보실 차례입니다. **영상을 잠깐 멈춰주세요.**
>
> 창 여섯 개를 하나씩 눌러서 어디 있는지 확인해보시고요,
> **Console 창을 일부러 닫았다가 되살려보세요.** 배치도 한번 흐트러뜨렸다가 되돌려보시고요.
>
> **마음껏 망가뜨리셔도 됩니다.** 되돌리는 법을 방금 배웠으니까요.

# **[00:14 ~ 00:23] Scene과 Game은 다른 눈입니다 — 오늘의 핵심**

✂️ **구분 자막**: `② Scene은 내 눈, Game은 카메라의 눈`

## **시연 A — 물건 놓고 시점 돌리기 (00:14 ~ 00:17)**

🖥 **화면**: Unity Editor, Scene 뷰

**1. 큐브 만들기** — Hierarchy 우클릭 → 3D Object → Cube

🗣
> "먼저 물건을 하나 놓겠습니다. Hierarchy에서 우클릭, 3D Object, Cube.
> 지난 시간에는 빈 그릇에 부품을 하나씩 붙여서 만들었죠? 이건 **Unity가 미리 조립해둔 완제품**입니다. 한 번에 나옵니다."

**2. 우클릭 드래그로 시점 회전**

🗣
> "이제 Scene 창에서 마우스 **오른쪽 버튼을 누른 채로 움직여** 보겠습니다.
> **화면이 빙글빙글 돌죠?** 이건 큐브가 도는 게 아니라 **제가 고개를 돌리는 겁니다.**"

**3. 휠로 줌 인 / 아웃**

🗣
> "휠을 굴리면 가까워지고 멀어집니다. 작업대에 얼굴을 들이미는 거예요."

**4. 일부러 길을 잃은 뒤 F 키**

🗣
> "이렇게 한참 돌리다 보면 **큐브가 어디 갔는지 모르게 됩니다.** 지금 저처럼요.
> 이럴 때는 **Hierarchy에서 큐브를 클릭하고, F 키**를 누르세요. **바로 앞으로 데려다줍니다.**
>
> **F 키. 오늘 배우는 것 중에 제일 자주 쓰게 되실 겁니다.**"

## **시연 B — Game 창은 왜 안 따라오는가 (00:17 ~ 00:19)**

**1. Game 탭 클릭**

🗣
> "이제 Game을 눌러보겠습니다. **아까랑 각도가 다르죠?**"

**2. 다시 Scene으로 가서 시점을 크게 돌린 뒤, 다시 Game**

🗣
> "다시 Scene으로 가서 화면을 마구 돌려보겠습니다. 이만큼 돌렸어요.
> 그리고 Game을 눌러봅니다.
>
> **하나도 안 바뀌었습니다.**
>
> 왜 그럴까요. **Scene은 여러분의 눈이고, Game은 카메라의 눈이기 때문입니다.**
> 제가 아무리 고개를 돌려도, 카메라는 자기 자리에서 자기가 보던 걸 계속 보고 있는 거예요."

**3. Main Camera 선택 → Inspector에서 Position 값 변경**

🗣
> "그럼 Game 화면을 바꾸려면 어떻게 해야 할까요? **카메라를 옮겨야 합니다.**
>
> Hierarchy에서 Main Camera를 고르고, Inspector에서 위치 숫자를 바꿔보겠습니다.
> 보세요. **이번엔 Game 화면이 바뀝니다.**"

🗣
> "정리하겠습니다. 오늘 이 한 문장만 가져가셔도 됩니다.
> **Game 화면을 바꾸고 싶으면, 화면을 돌리지 말고 카메라를 옮겨라.**"

- Scene과 Game을 오갈 때는 **탭을 클릭하는 마우스 움직임까지 화면에 보이게** 해주세요. 어느 창을 보고 있는지 놓치기 쉽습니다.
- 시점을 돌리는 장면은 **천천히**. 빠르게 돌리면 보는 사람이 멀미합니다.

## **⏸ 실습 ② (00:19 ~ 00:23)**

🗣
> "다시 멈추고 직접 해보세요.
>
> 큐브 하나 만드시고, Scene에서 시점을 마음껏 돌려보세요. 길을 잃으면 **F 키** 누르시면 됩니다.
> 그다음에 **Scene을 돌린 뒤 Game을 확인**해보세요. 안 바뀌는 걸 눈으로 보셔야 합니다.
> 마지막으로 **카메라를 옮겨서 Game 화면이 바뀌는 것까지** 확인해보시고요.
>
> **이 부분이 안 잡히면 3차시가 계속 헷갈립니다.** 여기는 시간을 좀 쓰셔도 좋습니다."

```
실습 ②
① Hierarchy 우클릭 → 3D Object → Cube
② Scene 창에서 우클릭 드래그 (시점 회전) · 휠 (줌)
③ 큐브 클릭 후 F 키 → 화면 정중앙으로
④ Scene 시점을 크게 돌린 뒤 → Game 탭 확인 (안 바뀜)
⑤ Main Camera 선택 → Inspector Position 변경 → Game 확인 (바뀜)
```

- **길 잃는 장면을 편집으로 잘라내지 마세요.** 강사도 길을 잃는다는 걸 보여주는 게 안심이 됩니다. F 키로 되찾는 장면까지 그대로 담아주세요.

# **[00:23 ~ 00:31] 재료함에서 만들어서 입힙니다**

✂️ **구분 자막**: `③ 재료를 만들어 입히기`

🗣
> "이번엔 **Project, 재료함**을 써보겠습니다.
> 큐브가 지금 밋밋한 회색이죠? **색을 입혀보겠습니다.** 물론 코드는 안 씁니다."

## **시연 (00:23 ~ 00:27)**

**1. 폴더 만들기** — Project의 Assets에서 우클릭 → Create → Folder → 이름 `Materials`

🗣
> "먼저 서랍을 하나 만들겠습니다. Assets에서 우클릭, Create, Folder. 이름은 Materials.
>
> 안 만들어도 동작은 합니다. 그런데 **나중에 파일이 백 개쯤 되면 서랍 없이는 못 찾습니다.**
> 지금부터 습관 들이시는 게 좋아요."

**2. 재료 만들기** — 폴더 안에서 우클릭 → Create → Material → 이름 `RedMat`

🗣
> "그 안에서 우클릭, Create, **Material**. 이름은 RedMat 이라고 하겠습니다.
> 이게 **색깔과 질감을 담는 재료**입니다. 페인트 통이라고 생각하시면 돼요."

**3. 색 고르기** — RedMat 클릭 → Inspector의 Base Map 색 상자 → 빨강

🗣
> "만든 재료를 한 번 클릭하면, **오른쪽 Inspector에 재료의 설정이 나옵니다.**
> **Base Map**이라고 적힌 줄 옆에 색깔 네모가 있죠? 눌러서 빨간색을 고르겠습니다.
>
> 버전에 따라 여기가 **Albedo**라고 적혀 있을 수도 있습니다. **같은 자리예요.** 이름만 다릅니다."

**4. 큐브에 입히기** — RedMat을 Scene의 큐브 위로 드래그

🗣
> "이제 이 재료를 **큐브 위로 끌어다 놓겠습니다.**
>
> **빨개졌습니다.**
>
> 지난 시간에 부품 붙일 때랑 똑같죠? **끌어다 놓기.** Unity는 거의 모든 게 이걸로 됩니다."

**5. 재료 색을 다시 바꿔 보이기** — RedMat의 색을 파랑으로

🗣
> "하나만 더 보여드릴게요. 재료의 색을 파란색으로 바꿔보겠습니다.
> **큐브도 같이 파래졌죠?**
>
> 이게 왜 좋냐면요. 큐브가 백 개 있어도 **재료 하나만 고치면 백 개가 다 바뀝니다.**
> 하나하나 칠할 필요가 없어요."

- **드래그는 아주 느리게.** 출발점(Project)과 도착점(큐브)을 둘 다 화면에 두고 움직여주세요.
- 색 고르는 창이 뜨는 순간 **잠깐 멈춰주세요.** 처음 보는 창이라 눈이 따라가지 못합니다.

## **⏸ 실습 ③ (00:27 ~ 00:31)**

🗣
> "멈추고 직접 해보세요.

# **비프로그래머 대상 표현 치환표**

전 차시에 걸쳐 적용함.

| 쓰지 말 것 | 이렇게 말할 것 |
| :--- | :--- |
| 변수, 필드 | **입력 칸**, **값** |
| 메서드, 함수 | **동작**, **기능** |
| public / private | (언급하지 않음) |
| 클래스, 인스턴스, 참조 | **끌어다 놓은 것** |
| 컴포넌트 | **부품** (영어 이름은 필요할 때만) |
| 프로퍼티 노출 | **인스펙터에 보이게 하기** |
| 이벤트 구독, 콜백 | **~할 때 같이 실행되게 연결** |
| 컴파일 | **저장하면 Unity가 알아서 반영** |
| 매개변수 | (다루지 않음) |
| 상속 | (다루지 않음) |
| 프레임 | (다루지 않음) |
| 크로스 플랫폼 | **한 번 만들면 어디든 간다** |
| 렌더링 | **화면에 그리기** |
| 빌드 | **완성해서 내보내기** |
