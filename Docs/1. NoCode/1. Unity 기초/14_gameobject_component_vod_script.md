# **[00:03 ~ 00:13] 빈 그릇에 부품 붙이기 — 오늘의 핵심 ①**

✂️ **구분 자막**: `① 붙이면 생기고, 빼면 사라진다`

## **레고 비유 되짚기 (00:03 ~ 00:05)**

🖥 **화면**: 교안 1번 섹션

🗣
> "11차시에 **레고 조립** 이야기를 했었죠. 오늘 그걸 **직접 해봅니다.**
>
> 먼저 **빈 그릇**을 하나 놓습니다. 아무것도 아닌 상태예요. **GameObject**라고 부릅니다.
> 그리고 여기에 **부품을 하나씩 끼웁니다.**
>
> 눈에 보이게 하고 싶다면? **보이게 하는 부품**을 붙입니다.
> 아래로 떨어지게 하고 싶다면? **중력을 받는 부품**을 붙이고요.
>
> 이게 전부입니다. **빈 그릇 + 부품들.** 바로 해보겠습니다."

## **에디터 시연 (00:05 ~ 00:10)**

🖥 **화면**: Unity Editor. **Hierarchy와 Inspector가 한 화면에 같이 보이게** 배치

**1. 빈 그릇 만들기** — Hierarchy 우클릭 → Create Empty

🗣
> "왼쪽 목록에서 오른쪽 클릭하고, Create Empty를 고릅니다.
> **빈 그릇이 하나 생겼습니다.** 그런데 화면엔 아무것도 안 보이죠?"

**2. Inspector 확인**

🗣
> "오른쪽 조종석을 보시면 지금 딱 하나만 있습니다. **Transform** 이라고 적혀 있죠.
> 이건 **'어디에, 얼마나 크게, 어느 방향으로 있는지'** 를 담당하는 **위치 부품**이에요.
>
> 이 부품은 **절대 뗄 수 없습니다.** 어디에 있는지 모르는 물건은 존재할 수가 없으니까요.
> 지금은 **위치만 있고 몸이 없는 상태**입니다."

**3. 모양 부품 붙이기** — Add Component → Mesh Filter → Mesh 를 Cube 로

🗣
> "조종석 아래쪽에 **Add Component**, '부품 추가' 버튼이 있습니다. 이걸 누르고 부품을 찾아 붙입니다.
>
> 먼저 **Mesh Filter**. **모양 부품**이에요. **어떤 모양인지**를 정합니다.
> 붙이고 나면 **Mesh** 라는 칸이 있는데, 여기를 **Cube**로 지정하겠습니다.
> 오른쪽 끝 동그란 아이콘 눌러서 목록에서 고르시면 됩니다.
>
> 자, 지정했습니다. 그런데 **아직도 화면엔 안 보이죠?**"

**4. 보이는 부품 붙이기** — Add Component → Mesh Renderer

🗣
> "하나가 더 필요합니다. **Mesh Renderer**, **보이는 부품**입니다.
>
> **네모가 나타났습니다.**
>
> 여기가 처음에 헷갈리는 지점이에요. 왜 두 개냐면요.
> **Mesh Filter는 옷의 본이고, Mesh Renderer는 실제로 입혀서 보여주는 겁니다.**
> **둘 다 있어야 화면에 나옵니다.** 하나만 붙이면 안 보여요."

**5. 떨어지는 부품 붙이기** — Add Component → Rigidbody → Play

🗣
> "이번엔 중력을 받는 부품을 붙여보겠습니다. **Rigidbody**입니다.
>
> Play를 눌러보겠습니다. **떨어집니다.**
>
> 여기서 중요한 이야기를 드릴게요.
> **저는 코드를 단 한 줄도 쓰지 않았습니다.** 부품 하나 붙였을 뿐이에요.
> 중력이 얼마고 낙하 속도가 어떻고, 그런 건 Unity가 이미 다 만들어뒀습니다."

**6. 부품 빼기** — Rigidbody 체크박스 해제 → Play

🗣
> "부품 이름 왼쪽에 체크박스가 있죠? 이걸 끄면 **그 부품은 잠시 쉽니다.**
> Play를 눌러보면 안 떨어지죠?
>
> **붙이면 생기고, 빼면 사라진다.** 이게 Unity의 방식입니다."

- **Add Component 검색창에 이름을 타이핑하는 장면**을 크게 담아주세요. 처음이라 어디에 치는지 모릅니다.
- Mesh Filter만 붙였을 때 **안 보이는 상태를 반드시 보여주고** Mesh Renderer를 붙이세요. 순서를 지켜야 "둘이 짝"이 이해됩니다.

## **⏸ 실습 ① (00:10 ~ 00:13)**

🗣
> "자, 이제 직접 해보실 차례입니다. **영상을 잠깐 멈춰주세요.**
>
> 빈 그릇 만들고, 부품 세 개 붙이고, **Play 눌러서 떨어지는 것까지** 확인하시면 됩니다.
> 마지막에 **Rigidbody 체크를 껐다 켜보시는 것**도 꼭 해보세요.
>
> 안 되셔도 괜찮습니다. 몇 번 다시 보셔도 되고요. 다 하셨으면 재생을 눌러주세요."

```
실습 ①
① Hierarchy 우클릭 → Create Empty
② Add Component → Mesh Filter → Mesh 를 Cube 로 지정
③ Add Component → Mesh Renderer   (여기서 화면에 나타남)
④ Add Component → Rigidbody
⑤ ▶ 눌러서 떨어지는지 확인
⑥ ▶ 끄고 Rigidbody 체크 해제 → 다시 ▶ (안 떨어짐)
```

# **[00:18 ~ 00:26] 세 창을 오가며 물건 다루기**

✂️ **구분 자막**: `② 세 창은 같은 물건을 보고 있다`

## **시연 A — 세 창 연동 (00:18 ~ 00:21)**

**1. 큐브 세 개 만들기** — Hierarchy 우클릭 → 3D Object → Cube ×3

🗣
> "큐브를 세 개 만들겠습니다. 우클릭, 3D Object, Cube. 세 번 반복합니다.
>
> 여기서 하나 짚고 갈게요. **아까는 부품을 세 개 붙여서 만들었는데, 이건 한 번에 나오죠?**
> **Unity가 그 부품들을 미리 붙여둔 완제품**이라서 그렇습니다.
>
> 그럼 아까 그건 왜 했냐. **완제품 안에 뭐가 들어 있는지 알아야 하니까요.**
> 앞으로는 완제품을 쓰시면 됩니다. 손으로 조립하는 건 오늘 그 한 번으로 충분해요."

🗣
> "그리고 화면에는 하나만 보이시죠? **세 개가 정확히 같은 자리에 겹쳐 있어서** 그렇습니다.
> 목록을 보시면 세 개가 다 있어요. **정상입니다.**"

**2. Hierarchy에서 클릭 → Scene 테두리 + Inspector 갱신**

🗣
> "목록에서 첫 번째를 클릭해보겠습니다.
> **작업대에 테두리가 생겼고**, 오른쪽 조종석에 **값이 떴습니다.**
>
> 두 번째를 클릭하면? **조종석 내용이 바뀝니다.** 다른 물건을 보고 있는 거예요."

**3. Inspector에서 Position X 변경 → Scene 즉시 이동**

🗣
> "이제 조종석에서 위치의 X 값을 3으로 바꿔보겠습니다.
> **작업대에서 바로 옆으로 갔습니다.** 겹쳐 있던 게 떨어져 나왔죠."

**4. Scene에서 다른 큐브 클릭 → Hierarchy 강조**

🗣
> "반대로도 됩니다. 작업대에서 남은 큐브를 클릭해보면, **목록에서 그 이름이 파랗게** 됩니다.
>
> **어디서 고르든 세 창이 다 같은 물건을 보고 있습니다.**"

## **시연 B — 도구 네 개 (00:21 ~ 00:24)**

🖥 **화면**: Scene 창 좌상단 도구 아이콘 **확대**

🗣
> "작업대 왼쪽 위에 아이콘이 줄지어 있습니다. **물건을 다루는 도구**예요."

**1. W — 이동**

🗣
> "**W를 누르면 이동**입니다. 물건에 **색깔 화살표**가 생겼죠?
>
> 빨간 건 좌우, 초록은 위아래, 파란 건 앞뒤입니다. 잡고 끌어보겠습니다.
>
> 여기서 **오른쪽 조종석을 같이 봐주세요.** 제가 끄는 동안 **숫자가 같이 변합니다.**
> **마우스로 끄는 거랑 숫자를 치는 거랑 똑같은 일**이라는 뜻이에요."

**2. E — 회전, R — 크기**

🗣
> "**E는 회전**입니다. 화살표가 **고리**로 바뀌었죠. 잡고 돌리면 회전 숫자가 변합니다.
> **R은 크기**고요. 손잡이를 끌면 크기 숫자가 변합니다.
>
> **W, E, R.** 이 세 개만 손에 익히시면 됩니다."

**3. 몸통을 잡고 끌어서 일부러 실패하기**

🗣
> "여기서 초보자분들이 제일 많이 겪는 걸 미리 보여드릴게요.
>
> 화살표를 안 잡고 **물건 몸통을 그냥 끌면** 이렇게 **아무 데로나 훅 가버립니다.**
> 지금 저 어디로 갔는지 모르겠죠?
>
> **Ctrl + Z**. 돌아왔습니다.
>
> **반드시 색깔 화살표를 잡고** 끌어주세요. 그래야 한 방향으로만 움직입니다."

**4. Inspector에 0, 0, 0 입력 + F2로 이름 바꾸기**

🗣
> "정말 어디로 갔는지 모르겠을 때는, **위치를 0, 0, 0 으로** 쳐보세요. **정확히 한가운데로 돌아옵니다.**
>
> 그리고 하나 더. **이름을 바꾸는 습관**을 지금부터 들이시면 좋습니다.
> 목록에서 이름을 **천천히 두 번 클릭**하거나, **F2**를 누르면 바꿀 수 있어요.
>
> `Cube (1)`, `Cube (2)` 이렇게 열 개쯤 쌓이면 **본인도 뭐가 뭔지 모릅니다.**"

- 도구를 바꿀 때 **키보드 키를 화면 자막으로 같이 띄워주세요.** `W` / `E` / `R` 이 언제 눌렸는지 안 보입니다.
- 몸통을 끌어서 실패하는 장면은 **자르지 말고 그대로** 담아주세요. 수강생이 똑같이 겪습니다.

## **⏸ 실습 ② (00:24 ~ 00:26)**

🗣
> "멈추고 직접 해보세요.

> 큐브 세 개 만드시고, 목록에서 클릭했다가 작업대에서 클릭했다가 해보세요.
> **나머지 창이 따라오는 걸 눈으로 확인하시는 게 목적**입니다.
>
> 그다음에 W, E, R 눌러가면서 옮기고 돌리고 키워보세요.
> **끄는 동안 오른쪽 숫자가 같이 변하는 것**을 꼭 확인해보시고요.

> 마음껏 망가뜨리셔도 됩니다. **Ctrl + Z 가 있습니다.**"

> **Inspector**에서 부품을 붙이고 값을 맞춥니다.
>
> 그리고 오늘의 핵심. **부모 하나만 움직이면 자식이 전부 따라옵니다.**
> 자동차에 부품을 **하나만** 붙여서 다섯 조각을 전부 돌리셨죠? 그게 증거입니다."

🗣
> "14차시를 세 줄로 정리하겠습니다.
>
> 첫째, **빈 그릇에 부품을 붙이면 생기고, 빼면 사라진다.**
> 둘째, **Hierarchy에서 묶으면, 부모를 움직일 때 자식이 전부 따라온다.**
> 셋째, **버튼 연결은 '누가 — 무엇을' 두 개만 고르면 된다.**"

🗣
> "오늘 여러분은 **부품을 조립하고, 묶고, 버튼으로 조종하는 것**까지 하셨습니다.
>
> 이건 자동차에만 쓰는 게 아니에요.
> 캐릭터의 팔다리, 화면에 올리는 버튼 묶음, 앞으로 뭘 만드시든 **계속 쓰게 될 방식**입니다.
>
> 그리고 네 시간째, **코드는 여전히 한 줄도 안 쓰셨습니다.** 충분히 잘하셨어요."

🗣
> "**15차시에서는 데이터 관리를 다룹니다.**
>
> 오늘 자동차 한 대 만드는 데 손이 꽤 갔죠. **다섯 대가 필요하면 어떻게 할까요?**
> 다음 시간에는 오늘 만든 자동차를 **'틀'로 만들어두고 찍어내듯 복제**하는 방법을 배웁니다.
>
> 그리고 오늘 이런 생각 하셨을 거예요. '0.55는 어느 쪽이지?', '왜 X를 90으로 하면 눕지?'
> **그건 20차시에서 제대로 다룹니다.** 지금은 몰라도 됩니다.

> 여유가 되시면 **색도 입혀보시고, 지붕도 얹어보세요.** 정답 없는 과제입니다.

# **비프로그래머 대상 표현 치환표**

전 차시에 걸쳐 적용함.

| 쓰지 말 것 | 이렇게 말할 것 |
| :--- | :--- |
| 변수, 필드 | **입력 칸**, **값** |
| 메서드, 함수 | **동작**, **기능** |
| public / private | (언급하지 않음) |
| 클래스, 인스턴스, 참조 | **끌어다 놓은 것** |
| 컴포넌트 | **부품** (영어 이름은 필요할 때만) |
| 프로퍼티 노출 | **인스펙터에 보이게 하기** |
| 이벤트 구독, 콜백 | **~할 때 같이 실행되게 연결** |
| 컴파일 | **저장하면 Unity가 알아서 반영** |
| 매개변수 | (다루지 않음) |
| 상속 | **묶으면 부모를 따라온다** (용어 자체는 쓰지 않음) |
| 프레임 | (다루지 않음) |
| 크로스 플랫폼 | **한 번 만들면 어디든 간다** |
| 렌더링 | **화면에 그리기** |
| 빌드 | **완성해서 내보내기** |
