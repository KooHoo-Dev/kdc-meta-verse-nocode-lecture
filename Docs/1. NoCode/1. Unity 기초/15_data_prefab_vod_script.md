>

>
> 그리고 오른쪽 조종석을 보세요. **바꾼 항목 이름이 굵게** 표시됩니다.

**2. Revert**

🗣
> "되돌리고 싶으면 그 항목 위에서 **우클릭, Revert.** 틀의 값으로 돌아갑니다."

**3. Unpack Completely → 검은 이름**

🗣
> "아예 **틀과 남남으로 만드는 방법**도 있습니다.
> 자동차 하나를 우클릭하고, **Prefab, Unpack Completely.**
>
> **이름이 검은색으로 변했습니다.** 이제 연결이 끊어진 거예요.
>
> 다시 틀을 고쳐보면 — **이 한 대만 안 바뀝니다.**"

🗣
> "그런데 실제로는 **거의 안 떼어냅니다.** 연결해두는 게 이득인 경우가 훨씬 많아요.
> '이 하나만 완전히 다르게 쓸 거다' 싶을 때만 쓰시면 됩니다."

🗣
> "오늘도 마지막으로 딱 한 번만 보고 가겠습니다.
> **외우실 필요 없고, 치실 필요도 없습니다.**"

🖥 **화면**: Project 창의 `Car.prefab` 파일과 Scene 의 다섯 대를 나란히 놓고 커서로 연결을 짚기

```
Prefabs/Car.prefab   ──→  [ 틀 하나 · 재료함에 보관 ]
        │
        ├──→  Scene 의 Car (파란 이름)
        ├──→  Scene 의 Car (파란 이름)
        └──→  Scene 의 Car (파란 이름)   ← 전부 같은 틀을 바라봄
```

🗣
> "오늘 하신 걸 정리하면 이렇습니다.
>
> **틀은 재료함에 파일 하나로 저장됩니다.** 그리고 Scene 에 놓인 것들은 **전부 그 파일 하나를 바라보고** 있어요.
>
> 그래서 파일 하나를 고치면 다 바뀌는 겁니다. **놓아둔 것들이 각자 정보를 갖고 있는 게 아니라, 틀을 참고하고 있는 거예요.**
>
> 코드로 하려면 훨씬 복잡합니다. 여러분은 **끌어다 놓기 한 번**으로 끝내셨고요.
>
> 지난 시간 결론과 똑같습니다. **끌어다 놓아서 될 일은, 코드로 하지 마라.**"

# **[00:47 ~ 00:50] 정리 & 다음 차시**

🖥 **화면**: 교안 7번 그림

🗣
> "오늘 배운 걸 그림 하나로 정리하겠습니다.
>

> 완성한 물건은 **재료함으로 되돌려 보내서 틀로** 만듭니다.
> 그리고 **틀 하나를 고치면 놓아둔 것이 전부 따라 바뀝니다.**"

🗣
> "15차시를 세 줄로 정리하겠습니다.
>
> 첫째, **재료는 끌어다 놓으면 들어온다.**
> 둘째, **틀은 붕어빵 틀이다.** 재료함에 끌어다 놓으면 만들어진다.
> 셋째, **틀 하나를 고치면 놓아둔 것이 전부 바뀐다.** 이름이 파란색이면 연결된 것."

🗣
> "오늘 여러분은 **같은 것을 여러 개 만드는 방법**을 배우셨습니다.
>
> 이건 나중에 게임 만들 때 그대로 씁니다. **표적 하나를 만들어서 수십 개로 늘릴 때**요.
> 그때 오늘 배운 게 없으면 표적을 하나하나 다 만들어야 합니다. **충분히 잘하셨어요.**"

🗣
> "**16차시에서는 화면에 그리는 부품들을 다룹니다.**

# **비프로그래머 대상 표현 치환표**

전 차시에 걸쳐 적용함.

| 쓰지 말 것 | 이렇게 말할 것 |
| :--- | :--- |
| 변수, 필드 | **입력 칸**, **값** |
| 메서드, 함수 | **동작**, **기능** |
| public / private | (언급하지 않음) |
| 클래스, 인스턴스, 참조 | **끌어다 놓은 것** |
| 컴포넌트 | **부품** (영어 이름은 필요할 때만) |
| 프로퍼티 노출 | **인스펙터에 보이게 하기** |
| 이벤트 구독, 콜백 | **~할 때 같이 실행되게 연결** |
| 컴파일 | **저장하면 Unity가 알아서 반영** |
| 매개변수 | (다루지 않음) |
| 상속 | (다루지 않음) |
| 프레임 | (다루지 않음) |
| 크로스 플랫폼 | **한 번 만들면 어디든 간다** |
| 렌더링 | **화면에 그리기** |
| 빌드 | **완성해서 내보내기** |
