🗣
> "같은 화면을 **휴대폰**에서도 보고 **큰 모니터**에서도 봅니다.
> 그런데 그냥 두면 **크기가 제멋대로**가 됩니다. 그걸 해결하는 부품이 있어요.
>
> Canvas 를 고르면 **Canvas Scaler** 라는 부품이 붙어 있습니다."

🗣
> "여기서 **UI Scale Mode** 를 보세요. 지금 **Constant Pixel Size** 로 되어 있습니다.
>
> 이건 **UI 픽셀 크기를 고정하는** 방식이에요. 화면이 커지면 UI가 **상대적으로 작아 보입니다.**
> 거의 안 씁니다.
>
> 이걸 **Scale With Screen Size** 로 바꾸겠습니다.
> 그리고 **Reference Resolution** 을 1920 곱하기 1080, **Match** 를 0.5 로 맞춥니다."

🖥 **화면**: 다시 Game 창에서 해상도를 여러 번 바꿔 **비율을 유지하며 커지고 작아지는** 것을 보여줌

🗣
> "이제 해상도를 바꿔보겠습니다. **비율을 유지하면서 같이 커지고 작아지죠?**
> 아까랑 느낌이 다릅니다.
>
> **UI를 만들 때 가장 먼저 하는 일이 이겁니다.** Canvas 만들면 바로 이 세 가지를 맞춰주세요."

🗣
> "Match 를 0.5 로 두는 이유만 짧게요.
> 0이면 가로에만, 1이면 세로에만 맞춥니다. **0.5 는 그 중간**이라 세로로 긴 휴대폰이든 가로로 넓은 모니터든 무난해요.
> **지금은 0.5로 두고 넘어가시면 됩니다.**"

> **그 확인까지 하셔야 오늘 실습이 끝난 겁니다.**
>
> 시간 넉넉히 쓰셔도 됩니다. 다 하셨으면 재생을 눌러주세요."

```
실습 ③
① Canvas 위에서 우클릭 → UI → Image  (네 번)
② 이름을 HealthBar / ScoreBox / TopBar / BottomBar 로 (F2)
③ 네 개의 Color 를 다르게
④ 앵커 프리셋을 Alt 누른 채로 선택
   HealthBar  → top-left      → Width 300, Height 40
   ScoreBox   → top-right     → Width 200, Height 60
   TopBar     → top-stretch   → Left 0, Right 0, Height 80
   BottomBar  → bottom-stretch → Left 0, Right 0, Height 120
⑤ HealthBar · ScoreBox 는 Pos X / Pos Y 를 ±20 으로 띄우기
⑥ Game 창 해상도를 여러 번 바꿔서 확인
```

 **트러블슈팅 — 대표 두 개만**
- **"앵커를 바꿨더니 물건이 이상한 데로 갔다"** → `Alt` 를 안 누르고 고른 경우입니다. **실수 장면을 한 번 보여주고 Alt 로 다시** 해주세요.
- **"Width 칸이 회색이라 못 고친다"** → `stretch` 앵커에서는 그 방향을 `Left`/`Right` 로 정합니다. **정상이라고** 안내하세요.

# **비프로그래머 대상 표현 치환표**

전 차시에 걸쳐 적용함.

| 쓰지 말 것 | 이렇게 말할 것 |
| :--- | :--- |
| 변수, 필드 | **입력 칸**, **값** |
| 메서드, 함수 | **동작**, **기능** |
| public / private | (언급하지 않음) |
| 클래스, 인스턴스, 참조 | **끌어다 놓은 것** |
| 컴포넌트 | **부품** (영어 이름은 필요할 때만) |
| 프로퍼티 노출 | **인스펙터에 보이게 하기** |
| 이벤트 구독, 콜백 | **~할 때 같이 실행되게 연결** |
| 컴파일 | **저장하면 Unity가 알아서 반영** |
| 매개변수 | (다루지 않음) |
| 상속 | (다루지 않음) |
| 프레임 | (다루지 않음) |
| 크로스 플랫폼 | **한 번 만들면 어디든 간다** |
| 렌더링 | **화면에 그리기** |
| 빌드 | **완성해서 내보내기** |
