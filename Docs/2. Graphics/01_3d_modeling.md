# **3D 모델링**
# **3D 모델링 개요**
3D 모델은 다각형(Polygon)으로 이루어진 입체적 객체입니다. 2D 그래픽이 평면에서 표현되는 반면, 3D 모델은 **가로(X), 세로(Y), 깊이(Z)** 축을 포함하여 입체적으로 표현됩니다.

- 3D 모델의 구성 요소:
    - **정점(Vertex)**: 점(Point)으로 이루어진 모델의 기본 단위.
    - **에지(Edge)**: 두 정점을 연결하는 선.
    - **면(Face)**: 최소 3개의 에지로 이루어진 단위.

대부분의 게임에서는 **삼각형(Tris)과 사각형(Quads)** 으로 모델을 구성하며, 최종적으로 게임 엔진에서는 삼각형 단위로 모델을 렌더링합니다.

## **3D 모델의 기본 요소**
### **폴리곤(Polygon)**
폴리곤은 3D 모델을 구성하는 기본 단위로, 삼각형과 사각형이 일반적으로 사용됩니다.

- **삼각형(Tris)**: 모든 3D 그래픽 소프트웨어와 게임 엔진에서 기본적으로 사용됨.
- **사각형(Quads)**: 모델링 작업에서 편집이 쉽지만, 최종적으로 삼각형으로 변환됨.

### **텍스처(Texture)**
3D 모델의 표면을 시각적으로 꾸미는 2D 이미지입니다.

- **UV 매핑(UV Mapping)**: 3D 모델을 평면(2D)으로 펼쳐서 텍스처를 적용하는 과정.

텍스처의 종류:

- **Albedo Map**: 기본 색상 및 디테일.
- **Normal Map**: 표면의 작은 굴곡을 표현하여 세부 디테일을 추가.
- **Specular Map**: 빛 반사를 조정.

### **쉐이더(Shader)**
쉐이더는 모델의 표면을 렌더링하는 작은 프로그램입니다.

- **PBR Shader (Physically Based Rendering)**: 현실적인 빛 반사와 그림자 표현.
- **Unlit Shader**: 조명의 영향을 받지 않는 간단한 쉐이더.

## **Vertex (버텍스, 정점)**
### **개념**
- **3D 공간에서 한 점을 의미**하며, 보통 **x, y, z 좌표값을 가진다**.
- 메시(Mesh)는 다수의 **버텍스로 구성**되며, 이들이 서로 연결되어 Edge(모서리)를 형성한다.
- 모든 3D 모델은 버텍스로 시작된다.

### **속성**
- 위치(Position): `(x, y, z)` 좌표로 정의됨.
- 색상(Color): 각 버텍스마다 색상을 저장할 수 있음.
- UV 좌표: 텍스처 매핑을 위한 좌표를 포함.
- 법선(Normal): 조명 계산에 사용되는 벡터.

### **역할**
- 모델의 형태를 결정하는 가장 기본적인 요소.
- 쉐이더나 조명 시스템에서 버텍스 데이터를 기반으로 **조명 연산 및 변형이 수행됨**.
- **애니메이션, 변형(Morphing)** 등의 연산에 사용됨.

## **Edge (엣지, 모서리)**
### **개념**
- **두 개의 버텍스를 연결하는 선분**을 의미.
- 메시를 구성하는 기본적인 요소 중 하나로, 페이스(Face)를 형성하는 데 필수적임.
- **Edge 자체는 면(Face)을 가지지 않으며, 최소한 세 개의 Edge가 있어야 하나의 Face가 생성됨**.

## **Face (페이스, 면, 폴리곤)**
### **개념**
- **세 개 이상의 버텍스(Vertex)와 Edge(엣지)로 구성된 2D 표면**.
- 일반적으로 폴리곤(Polygon)이라고 하며, 대부분의 3D 엔진에서는 **삼각형(Tris) 또는 사각형(Quads)으로 처리됨**.

### **Face의 유형**
- **Triangle (삼각형)**: 3개의 버텍스로 구성됨. **게임 엔진에서 기본적으로 삼각형 기반으로 렌더링됨**.
- **Quad (사각형)**: 4개의 버텍스로 구성됨. 모델링에서 많이 사용되지만, 게임 엔진에서 삼각형으로 변환됨.
- **Ngon (엔곤)**: 5개 이상의 버텍스로 구성된 면. 실시간 렌더링에서 삼각형으로 변환해야 하므로 지양됨.

### **Face의 역할**
- **렌더링 단위**: GPU는 삼각형을 기반으로 렌더링을 수행.
- **텍스처 매핑**: 페이스의 UV 좌표를 설정하여 텍스처를 적용.
- **라이팅 계산**: 조명이 적용되는 기본 단위.

## **Vertex, Edge, Face의 관계**
| 요소 | 개념 | 특징 |
| --- | --- | --- |
| **Vertex (정점)** | 3D 공간에서 하나의 점 | `x, y, z` 좌표, 법선, UV 정보 포함 |
| **Edge (모서리)** | 두 개의 버텍스를 연결하는 선 | 메시의 형태를 결정 |
| **Face (면, 폴리곤)** | 세 개 이상의 버텍스로 이루어진 표면 | 렌더링과 텍스처 매핑의 기본 단위 |

# **3D 모델의 표면과 법선 벡터(Normal Vector)**
### **폴리곤의 표면**
폴리곤(Polygon)은 여러 개의 정점(Vertex)과 에지(Edge)로 이루어진 면(Face)입니다. 이 면은 특정 방향을 향하고 있으며, 법선 벡터(Normal Vector)를 통해 그 방향을 정의합니다.

### **법선 벡터(Normal Vector)?**
법선 벡터(Normal Vector)는 **폴리곤의 표면이 바라보는 방향을 나타내는 단위 벡터(길이가 1인 벡터)** 입니다.

**법선 벡터가 중요한 이유:**

- **광원 연산**: 빛이 표면에 닿을 때, 법선 벡터를 이용하여 조명의 영향을 계산.
- **쉐이딩(Shading) 연산**: 법선 벡터를 활용하여 표면의 음영과 밝기 계산.
- **물리 엔진과 충돌 판정**: 오브젝트가 충돌할 때 법선 방향을 기준으로 반응.

### **법선 벡터의 종류**
### **(1) 폴리곤 법선(Face Normal)**
- 한 폴리곤(면) 전체가 공유하는 단일한 법선 벡터.
- 각 면이 명확히 구분되는 **Low-poly 스타일(도트 감성, 셀 셰이딩)** 에서 주로 사용됨.

### **(2) 정점 법선(Vertex Normal)**
- 각 정점마다 개별적인 법선 벡터를 설정.
- 법선 벡터가 부드럽게 연결되어 **Smooth Shading(부드러운 셰이딩)** 표현 가능.

### **법선 벡터의 조작**
### **(1) 법선 벡터 스무딩 (Normal Smoothing)**
- 법선 벡터를 인접한 면들과 평균 내어 부드러운 표면을 만듦.
- 유니티에서는 **Normals 옵션**을 통해 조정 가능.

### **(2) 노멀 맵(Normal Map)**
- 낮은 폴리곤 모델에서도 고해상도의 디테일을 표현할 수 있도록 도와줌.
- 고해상도 모델에서 계산한 법선 정보를 텍스처로 저장하여 저해상도 모델에 적용.

# **리깅(Rigging)**
### **리깅?**
리깅(Rigging)은 3D 모델에 본(Bone, 뼈대)을 추가하여 애니메이션을 적용할 수 있도록 하는 과정입니다.

- 리깅된 모델은 **애니메이션(걷기, 점프, 공격 등)** 을 수행할 수 있음.
- 캐릭터뿐만 아니라 기계, 동물, 로봇 등 다양한 오브젝트에도 사용됨.

### **리깅의 주요 요소**
### **(1) 본(Bone)**
본은 3D 모델이 움직이는 구조를 정의하는 가상의 뼈대입니다.

- **루트 본(Root Bone)**: 모델 전체를 제어.
- **서브 본(Sub Bone)**: 개별적인 신체 부위를 제어.

### **(2) 스킨(Skin) & 웨이트 페인팅(Weight Painting)**
- 본과 모델을 연결하는 과정.
- 웨이트 페인팅(Weight Painting)을 사용하여 특정 본이 어느 정도 영향을 미칠지를 조정.

### **(3) IK(Inverse Kinematics) & FK(Forward Kinematics)**
애니메이션에서 많이 사용하는 기술.

- **FK(Forward Kinematics)**: 상위 본이 움직이면 하위 본이 영향을 받음.
- **IK(Inverse Kinematics)**: 손이나 발을 특정 위치에 고정하고 자연스럽게 움직이도록 설정.

# **High Poly vs. Low Poly**
## **High Poly (하이 폴리)**
### **개념**
- **폴리곤 개수가 많고 정밀한 모델**.
- 수십만~수백만 개의 폴리곤으로 이루어짐.
- **디테일이 뛰어나며, 현실감 있는 그래픽 표현이 가능**.

### **특징**
- **고해상도 모델링**
- **세밀한 곡선 표현 가능**
- **실사 수준의 디테일 제공**
- **높은 폴리곤 수로 인해 렌더링 비용이 큼**

### **활용 분야**
- **CGI & VFX**: 영화, 광고, 애니메이션 등에서 정밀한 렌더링이 필요할 때 사용됨.
- **3D 스컬프팅**: ZBrush, Blender, Mudbox 등에서 고해상도 조각 모델 제작.
- **게임용 베이크(Bake) 모델링**: High Poly 모델을 제작한 후, **Normal Map**을 Low Poly 모델에 적용하여 디테일을 유지함.
- **3D 프린팅**: 실제 조형물을 제작하기 위해 고해상도 메쉬 필요.

### **High Poly의 장점 & 단점**
| 장점 | 단점 |
| --- | --- |
| 극도로 사실적인 디테일 표현 가능 | 높은 하드웨어 성능 요구 |
| 복잡한 곡선과 텍스처를 자연스럽게 표현 | 게임 및 실시간 렌더링에는 적합하지 않음 |
| 조명, 쉐이딩 효과가 더 정밀함 | 렌더링 시간이 길어짐 |

### **High Poly 예제**
- 3D 캐릭터의 주름, 피부 질감, 머리카락 한 올 한 올까지 표현된 모델.
- 영화에서 사용되는 초고해상도 CG 캐릭터.
- 제품 디자인(자동차, 전자기기 등)에서 디테일한 시각화 렌더링.

## **Low Poly (로우 폴리)**
### **개념**
- **최소한의 폴리곤 개수로 모델을 구성하는 기법**.
- 일반적으로 수백~수천 개의 폴리곤을 가짐.
- **실시간 렌더링과 게임 개발에서 중요한 최적화 기법**.

### **특징**
✔ **렌더링 속도가 빠름**

✔ **경량 모델로 하드웨어 부담이 적음**

✔ **각진 형태가 강조되며, 특유의 아트 스타일을 가질 수 있음**

✔ **디테일이 부족할 수 있음**

### **활용 분야**
- **비디오 게임**: 실시간 렌더링이 필요한 게임에서는 반드시 Low Poly 모델을 사용.
- **VR/AR**: 고사양 그래픽을 처리하기 어려운 모바일 및 VR 기기에서 필수.
- **모바일 게임**: 성능 최적화를 위해 최적화된 Low Poly 모델이 중요함.
- **웹 3D 모델링**: 웹GL, Three.js, Babylon.js 등의 웹 기반 3D 엔진에서 사용됨.

### **Low Poly의 장점 & 단점**
| 장점 | 단점 |
| --- | --- |
| 실시간 렌더링에 최적화됨 | 디테일이 제한적 |
| 성능이 뛰어나고 다양한 플랫폼에서 사용 가능 | 사실적인 표현이 어려움 |
| 텍스처와 Normal Map으로 디테일을 보완 가능 | 애니메이션 적용 시 Edge가 부드럽지 않을 수 있음 |

### **Low Poly 예제**
- 모바일 게임의 단순화된 캐릭터 및 환경 모델.
- 마인크래프트(Minecraft)처럼 Low Poly 스타일을 활용한 게임.
- Unity나 Unreal Engine에서 최적화된 NPC 및 배경 모델.

## **High Poly vs. Low Poly 비교**
| 항목 | High Poly | Low Poly |
| --- | --- | --- |
| 폴리곤 개수 | 수십만~수백만 개 | 수백~수천 개 |
| 그래픽 스타일 | 사실적인 표현 | 단순하고 각진 스타일 |
| 성능 요구 | 높은 성능 필요 | 낮은 성능에서도 원활 |
| 사용 사례 | CGI, 영화, VFX, 3D 프린팅 | 게임, VR/AR, 모바일, 실시간 렌더링 |
| 최적화 필요성 | 반드시 Low Poly로 변환 필요 | 최적화 작업이 적음 |
| 애니메이션 | 세밀한 애니메이션 가능 | 과한 변형 시 왜곡 발생 |

- **High Poly**: 고품질 디테일을 요구하는 **영화, 애니메이션, 3D 프린팅**에서 사용.
- **Low Poly**: 실시간 렌더링이 중요한 **게임, VR/AR, 모바일**에서 필수.
- **게임 개발에서는 보통 High Poly에서 Low Poly로 변환 후 Normal Map을 적용하여 최적화**.
