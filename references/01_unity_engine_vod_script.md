>
> 게임도 만들고, VR도 만들고, 건축 시각화도 하고, 자동차 회사 카탈로그도 Unity로 만듭니다."

🖥 **화면**: 교안의 비유 인용 블록. **각 항목을 말할 때 마우스 커서로 해당 줄을 짚어주세요.**

🗣
> "제가 좋아하는 비유가 하나 있습니다. Unity는 **종합 영화 스튜디오**예요.
>
> 영화를 찍는다고 생각해보세요. 카메라가 필요하겠죠? Unity에도 **Camera**가 있습니다.
> 조명이랑 세트가 필요하겠죠? **Lighting**과 **Scene**이 있고요.
> 배우가 있어야 하겠죠? 그게 **GameObject**입니다.
>
> 그런데 배우한테 각본이 없으면 뭘 해야 할지 모르겠죠? 그 각본이 바로 **스크립트**입니다.

> Unity에서는 그걸 **Build**라고 부릅니다. PC, 모바일, 콘솔, 웹, VR 어디든 나갑니다."

🖥 **화면**: 교안 3.1 표 (짧게)

🗣
> "Unity는 얼굴이 두 개입니다.
>

> 다른 하나는 **Unity Runtime**. 다 만든 게임이 실제로 돌아가는 상태예요. 플레이어가 보는 쪽입니다.
>
> 요리에 비유하면 **주방과 완성된 요리** 같은 겁니다. 주방은 여러분이 쓰는 공간이고, 손님은 요리만 받죠."

🖥 **화면 전환**: **Unity Editor로 전환** — 이번 차시의 첫 화면 전환

🗣
> "직접 보여드리겠습니다. 지금 이 복잡한 화면이 **Unity Editor**입니다.
>
> 창이 여러 개 있어서 정신없어 보이시죠? **지금은 하나도 몰라도 됩니다.**
> 각 창이 뭘 하는지는 **다음 차시에서 하나씩** 다룹니다. 오늘은 제가 클릭하는 것만 봐주세요.
>
> 여기 위쪽에 **삼각형 모양 Play 버튼**이 있습니다. 이걸 누르면 게임이 실행돼요.
> 그런데 이건 **에디터 안에서 흉내를 내고 있는 겁니다.** 아직 진짜 게임은 아니에요."

🖥 **화면 전환**: 미리 빌드해둔 실행 파일 실행

🗣

> **이게 Runtime, 다 만들어진 상태입니다.**"

# **[00:16 ~ 00:27] 부품을 조립한다 — 오늘의 핵심 ①**

## **레고 비유 (00:16 ~ 00:18)**

🖥 **화면**: 교안 3.2 섹션으로 잠깐 복귀

🗣
> "자, 여기가 오늘 가장 중요한 부분 중 하나입니다.
>
> Unity에서 물건을 만드는 방식은 **레고 조립과 아주 비슷합니다.**
>
> 먼저 **빈 그릇**을 하나 놓습니다. 아무것도 아닌 상태예요. 이걸 **GameObject**라고 부릅니다.
> 그리고 여기에 **부품을 하나씩 끼웁니다.**
>
> 눈에 보이게 하고 싶다면? **'보이게 하는 부품'** 을 붙입니다.
> 아래로 떨어지게 하고 싶다면? **'중력을 받는 부품'** 을 붙입니다.
>
> 이게 전부입니다. **빈 그릇 + 부품들.**
> 말로만 하면 안 와닿으실 테니 직접 해보겠습니다."

## **에디터 시연 (00:18 ~ 00:23)**

🖥 **화면**: Unity Editor

**1. 빈 그릇 만들기** — Hierarchy 우클릭 → Create Empty

🗣
> "왼쪽 목록에서 오른쪽 클릭하고, Create Empty를 고릅니다.
> **빈 그릇이 하나 생겼습니다.** 오른쪽 화면을 보세요."

**2. Inspector 확인**

🗣
> "오른쪽에 있는 이 창을 **Inspector**라고 부릅니다. **'선택한 물건의 부품 목록'** 이라고 생각하시면 돼요.
> 오늘 이 창을 계속 쓸 거니까 위치만 기억해두세요.
>
> 지금은 딱 하나만 있죠? **Transform** 이라고 적혀 있습니다.
> 이건 **'어디에, 얼마나 크게, 어느 방향으로 있는지'** 를 담당하는 부품이에요.
>
> 이 부품은 **절대 뗄 수 없습니다.** 어디에 있는지 모르는 물건은 존재할 수가 없으니까요.
> 그런데 아직 화면에는 아무것도 안 보이죠? **위치만 있고 몸이 없는 상태**입니다."

**3. 보이는 부품 붙이기** — Add Component → Mesh Filter (Mesh: Cube) → Mesh Renderer

🗣
> "Inspector 아래쪽에 **Add Component**, '부품 추가' 버튼이 있습니다. 이걸 누르고 부품을 찾아 붙입니다.
>
> 보이게 하는 부품을 붙였습니다. **네모가 나타났죠?**
> 아까 그 빈 그릇에 몸이 생긴 겁니다."

**4. 떨어지는 부품 붙이기** — Add Component → Rigidbody → Play

🗣
> "이번엔 중력을 받는 부품을 붙여보겠습니다. 이름은 **Rigidbody**입니다.
>
> Play를 눌러보겠습니다. **떨어집니다.**
>
> 여기서 중요한 이야기를 드릴게요.
> **저는 코드를 단 한 줄도 쓰지 않았습니다.** 부품 하나 붙였을 뿐이에요.
> 중력이 얼마고 낙하 속도가 어떻고, 그런 건 Unity가 이미 다 만들어뒀습니다. 우리는 갖다 붙이기만 하면 돼요."

**5. 부품 빼기** — Rigidbody 체크박스 해제 → Play

🗣
> "부품 이름 왼쪽에 체크박스가 있죠? 이걸 끄면 **그 부품은 잠시 쉽니다.**
> Play를 눌러보면 안 떨어지죠?
>
> **붙이면 생기고, 빼면 사라진다.** 이게 Unity의 방식입니다."

## **⏸ 실습 ① (00:23 ~ 00:27)**

>
> 여러분은 지금 **그 조정하는 쪽 일을 하고 계신 겁니다.**"

2. `Target Color` 색상 칸 클릭 → 파란색 선택
   🗣 "색을 고르는 칸도 있습니다. 그림판에서 색 고르는 것과 똑같죠?
   > 지금 고른 색은 **아직 적용되지 않습니다.** 잠시 후에 버튼으로 적용할 거예요."

# **비프로그래머 대상 표현 치환표 프롬프트**

전 차시에 걸쳐 적용함.

| 쓰지 말 것 | 이렇게 말할 것 |
| :--- | :--- |
| 변수, 필드 | **입력 칸**, **값** |
| 메서드, 함수 | **동작**, **기능** |
| public / private | (언급하지 않음) |
| 클래스, 인스턴스, 참조 | **끌어다 놓은 것** |
| 컴포넌트 | **부품** (영어 이름은 필요할 때만) |
| 프로퍼티 노출 | **인스펙터에 보이게 하기** |
| 이벤트 구독, 콜백 | **~할 때 같이 실행되게 연결** |
| 컴파일 | **저장하면 Unity가 알아서 반영** |
| 매개변수 | (다루지 않음) |
| 상속 | (다루지 않음) |
| 프레임 | (다루지 않음) |
| 크로스 플랫폼 | **한 번 만들면 어디든 간다** |
| 렌더링 | **화면에 그리기** |
| 빌드 | **완성해서 내보내기** |
